### 1. 产品定位与多端分工

open-immerse 的核心目标是成为科研人员的**个人研究操作系统**：以结构化文献库为知识底座，覆盖「读 → 理解 → 记 → 想 → 写」的完整链路，并通过不同端适配不同场景。

| 端 | 核心场景 | 主要能力 | 设计原则 |
|----|----------|----------|----------|
| **桌面端**（扩展 + Electron） | 深度阅读 + 论文写作 | 高精度 PDF 对照、公式精准呈现、笔记、文献管理、LaTeX 写作辅助与导出 | 大屏、精确操作、长时间沉浸 |
| **手机端** | 听论文 + 轻量回顾与捕捉 | 论文播客/讲解音频、语音问答、快速回顾、语音笔记、轻量写作灵感 | 碎片时间、听觉优先、低认知负担 |
| **共享底座** | 知识库 | 文献、译文、块、笔记、写作项目、引用关系 | 一次处理，多端复用 |

**关键原则**：
- 桌面负责“深读 + 写作产出”。
- 手机负责“听懂 + 记住 + 灵感捕捉”。
- 写作内容与阅读内容进入同一知识库，形成闭环。
- 手机支持轻量写作（语音转段落、大纲补充），但重编辑仍在桌面。

### 2. 设计原则（补充）

在原有原则基础上增加：

- **知识库统一**：阅读产生的结构化内容（块、译文、笔记）与写作项目共享同一套数据模型与检索能力。
- **场景适配而非功能复制**：手机不做完整 PDF 阅读器，桌面不做以音频为主的消费界面。
- **写作渐进**：先做“基于知识库的生成与导出”，再考虑轻量编辑器，避免过早与 Overleaf 竞争。
- **听觉化一等公民**：音频生成、播放、章节导航作为手机端核心路径设计，而非附加功能。

### 5. 知识库与写作域设计

**统一知识库**以文献为核心实体，扩展写作项目：

- `Document`：论文（含原文、译文、块、公式决策、笔记锚点）。
- `Note`：用户笔记（可挂到块或独立）。
- `WritingProject`：写作项目，关联多个 `Document`。
- `Section`：论文章节（Introduction、Related Work 等），可包含生成内容与用户编辑。
- `CitationLink`：写作内容与来源论文/块的引用关系。

**写作流程（桌面为主）**：
1. 从文献库选择相关论文创建 `WritingProject`。
2. AI 基于关联论文 + 用户笔记/想法生成大纲与初稿段落（LaTeX）。
3. 用户在桌面编辑器中修改，系统维护引用关系。
4. 一键导出标准 arXiv 风格 LaTeX 项目。

**手机轻量写作**：
- 语音输入想法 → 自动归入某个 `WritingProject` 的对应章节。
- 生成或补充段落草稿，回桌面后可继续编辑。

### 6. 手机端听觉化设计

手机端以「听论文」为核心路径：

- **播客生成**：基于译文 + 块结构 + 用户笔记，生成 10–15 分钟结构化讲解（贡献、方法、实验、局限）。
- **按需讲解**：语音或点击触发“讲一下这个公式 / 这个章节”。
- **语音问答**：结合论文内容与历史笔记进行对话，支持语音输入输出。
- **播放体验**：章节导航、倍速、后台播放、进度与桌面阅读位置关联（可选）。
- **轻量回顾**：打开论文优先展示“上次听到哪里 + 关键卡片 + 我的笔记摘要”。

音频脚本生成放在 `core/audio/`，TTS 调用通过 `platform` 适配（支持云 API 与本地模型）。

### 7. 多端数据与同步

- 所有结构化数据（文献、笔记、写作项目、音频脚本元数据）通过统一 `platform.library` 访问。
- 桌面：SQLite + 文件系统。
- 手机：本地数据库 + 可选云同步。
- 扩展：IndexedDB（过渡期）。
- 原 PDF、音频文件、导出 LaTeX 包按平台存储策略处理。
- 云同步（原 F10）作为可选能力，密钥与敏感内容由用户控制。
