### 8.1 权威数据

结构化 JSON 文档模型是权威；Markdown / LaTeX 是导出投影。核心类型沿用 [草案 02](./docs/architecture/02_数据协议与高精度规格迁移_草案.md) §3–§9 的 `ContentBlock`、`AcceptedPageRevision`、`FormulaCandidate`、`FormulaDecision`、`EvaluationResult`、`ContentAnchor`、`CoordinateFrame`，落入 `contracts`；草案 02 的 `TranslationRecord` 由 `StoredTranslationBlock` 取代（§8.1.1）。坐标统一为「CropBox 经旋转后的可见页面，左上原点，0–1 归一化」。

唯一的例外是译文正文：每个译文区块的 `markdown` 字段以 Markdown 存储（D6）。这只是**区块内**的显示格式；块号、顺序、坐标、公式决策仍由 JSON 模型给出，译文通过 `sourceBlockId` 挂在采用版本的块上。

#### 8.1.1 译文区块记录（D6）

决定（Wisdom 2026-10-30 17:27，17:32 修订；Loom 方案 D6 以 2026-10-30 再次确认的版本为准）：译文**按段落分块**存储，不存成整篇 `.md`，也不按整页存。每个原文段落级文本块的每个译文版本一条记录：分块单位就是采用版本中带稳定块号的文本块。正文字段是 Markdown，其余是结构化字段。左右对照、点击互跳、单块重译、缓存都以这个块为单位。`translatePage` 只是按页提交任务的入口，结果仍然按块落库。

**哪些块是翻译块**（Loom 2026-10-30 结论；`block-scope.ts` 是唯一判定处，PRD AC-58）：

| 块类型 | 是否翻译块 | 显示 |
| --- | --- | --- |
| 正文段落、标题、图表题注、脚注、列表项、引用块 | 是 | 译文栏显示该块的 `markdown` |
| 表格、图 | 否 | 原文裁图；只有它们的题注是翻译块 |
| 独立公式 | 否 | 走公式回退链（§7.5），不进翻译 |

列表项、引用块、标题的层级与标记由 JSON 模型的块类型给出，`markdown` 只存块内文字，不带 `- `、`> `、`#` 这类标记（见写入流程第 3 步）。

```ts
// packages/contracts/src/translation.ts —— 拟议；字段以方案 §3.3.2 为起点
type StoredTranslationBlock = Readonly<{
  documentId: DocumentId;
  revisionId: PageRevisionId;            // 规格补充：绑定采用版本；重解析后内容不变的块按 cacheKey 复用
  sourceBlockId: BlockId;                // 对齐键：左右对照、点击互跳、滚动同步
  blockKind: 'paragraph' | 'heading' | 'caption' | 'footnote' | 'list_item' | 'quote'; // 规格补充；进缓存键
  version: number;                       // 同一区块的译文版本号，重译 +1
  status: 'success' | 'failed' | 'retranslating';
  failureKind: 'check_failed' | 'network' | 'model_error' | null; // 规格补充；只有 failed 才有值，供「重译未成功」的原因提示
  markdown: string | null;               // 只有 success 才有值；只含写成 LaTeX 的公式（verified-latex、source-checked-latex、format-checked-latex，§7.5），不含裁图与占位框
  crops: readonly FormulaCropRef[];      // 架构评审 P0-4：不写进 markdown 的公式（source-crop、page-placeholder）在块中的位置；没有时为空数组
  formatVersion: 'oi-md/1';
  model: Readonly<{ providerId: string; modelId: string }>;
  targetLang: 'zh-CN';                   // 规格补充
  cacheKey: string;
  formulaDigest: string;                 // 规格补充：写入时的公式决定摘要，读取时与当前比对（见「缓存键」）
  check: Readonly<{ result: 'passed' | 'failed' | 'not_run'; codes: readonly string[] }>;
  updatedAt: string;                     // ISO 8601
}>;
type FormulaCropRef = Readonly<{
  fragmentId: string;                    // 受保护片段表里的公式片段
  at: number;                            // 在 markdown 中的插入位置（UTF-16 偏移，转义与还原完成后计算）
  display: 'inline' | 'block';
  kind: 'crop' | 'page_link';            // crop = 原页裁图；page_link = 占位框（§7.5 第 6 步）
  assetId: AssetId | null;               // kind = crop 时为当前采用版本的裁图；内容哈希已计入 formulaDigest
  page: number | null;                   // kind = page_link 时为原文页码
}>;
```

**方言 `oi-md/1`**：CommonMark + GFM 表格与删除线 + `$…$` / `$$…$$` 公式；不含 HTML、wikilink、图片。图、表、公式本身是单独的区块，不进译文文字。

**未核验公式的裁图（架构评审 P0-4，Wisdom 2026-10-30 19:57 批准；在建立 `contracts/src/translation.ts` 之前定死）**：

- `markdown` 字符串里只出现写成 LaTeX 的公式的 `$…$` / `$$…$$`：已核验公式（`verified-latex`），「源码核对」（`source-checked-latex`，Wisdom 2026-10-30 22:15），以及程序核对通过的 `format-checked-latex`（Wisdom 2026-10-31 01:14；`checked-latex` 已并入）。其余情况（`source-crop`、`page-placeholder`）不把候选 LaTeX 写进去冒充已核验，也不在 Markdown 里发明图片或占位语法；`oi-md/1` 仍然不含图片与 HTML。`markdown` 本身不区分这三种 LaTeX 公式，区分由 `getBlocks` 的标记给出（「规则」末条）。
- 片段表保存每个公式片段的显示决定。`source-crop` 带裁图 `assetId`；`page-placeholder` 带页码。位置记在记录的 `crops` 字段（`at` 是 `markdown` 中的插入位置）。
- `getBlocks` 在 core 里生成每块的 `MdDocument`：先经 `markdown` 的 seam 解析 `markdown`，再在每个 `at` 处插入 `MdFormulaCrop` 节点。`kind = crop` 时是 `{ type: 'formula_crop', display, assetId, fragmentId }`；`kind = page_link` 时是 `{ type: 'formula_crop', display, kind: 'page_link', page, fragmentId }`，界面文字暂定「图见原文第 N 页（点击查看）」，点击后左侧原文跳到该页（样式待 Loom）。源码区间是 `at` 处的零长度区间。写成 LaTeX 的公式是普通的 math 节点。reader 只渲染这个文档，裁图经 ui-kit 的裁图组件与 `oi-asset://` 显示；行内裁图的尺寸与基线对齐等视觉由 Loom 定（DESIGN.md §3.3、§3.4、DS-14）。
- 这是 `oi-md/1` 的一部分，不是以后的方言升级：缓存键里的 `formatVersion` 不因此改变。`formulaDigest` 继续覆盖显示决定与裁图内容哈希（「缓存键」一节）。

**写入流程**（全部在 `translation` core，顺序固定）：

1. 抽取：原文区块 → 占位文本（`⟦fN⟧`）+ 受保护片段表（公式、编号、引用；每个公式片段带当前采用版本的显示决定，`source-crop` 时带裁图 `assetId`，`page-placeholder` 时带页码，见「缓存键」）+ 公式决定摘要 `formulaDigest`（v1 审查 §4.9）。
2. 完整性校验 `integrity-check.ts`：占位符的数量、顺序、对应关系与原文 100% 一致，数字与引用一致（AC-03）。不过 → 写一条 `failed` 记录，`failureKind = 'check_failed'`，`markdown` 为 `null`，`check.codes` 记原因。请求本身失败（网络、超时）记 `network`，服务商返回错误或无法解析的输出记 `model_error`，同样不写 `markdown`。`ProviderFailure.kind` 怎么归进这三类，只在下表，不另起枚举。解析、OCR、Jev 的用户可见提示也只用「校验失败」「网络错误」「模型错误」这三个词；Jev 的 `unavailable/auth`、预算到顶、评分不可用的三选一继续用已有文案（填 Key、已达上限、三选一），不新造第四类用户状态。界面具体句子待 Loom。

| `ProviderFailure.kind` 或失败来源 | `failureKind` | 用户下一步（已有入口） |
| --- | --- | --- |
| `timeout` | `network` | 重试 |
| `rate_limited` | `network` | 重试（遵守 `retryAfterMs`，不盲重发） |
| `auth`、`quota` | `model_error` | 设置里的 Key / 预算；文案可带原因码 |
| `invalid_request`、`too_large`、`service_failed` | `model_error` | 重试或更换翻译服务 |
| 完整性校验不过 | `check_failed` | 重译；不把候选 LaTeX 写进 markdown |
3. 还原 `markdown-restore.ts`：先用 CommonMark 的反斜杠转义处理模型文字中的 `$`、`<`、`&`、`[[`，以及行首的 `#`、`>`、`-`、`+`、`*`、`数字.` / `数字)`（模型生成的 HTML 因此只会显示为文字，块内文字也不会被解析成标题、列表或引用），再还原占位符：`verified-latex`、`source-checked-latex` 与 `format-checked-latex` 片段还原为片段表里的 LaTeX，行内写 `$…$`，行间写独占一行的 `$$…$$`；`source-crop` 与 `page-placeholder` 片段不写任何字符，只在 `crops` 里记下 `fragmentId`、行内 / 行间、`kind`、`assetId` 或页码，以及插入位置 `at`（整串拼好之后计算）。顺序不能反：先还原再转义会把公式里的符号也转义掉。
4. 复核：经 `markdown` 的 seam 调 `extractMath(markdown)`，得到的公式序列必须与片段表中写成 LaTeX 的片段（`verified-latex`、`source-checked-latex`、`format-checked-latex`）逐个相等（`source-crop` 与 `page-placeholder` 片段的 LaTeX 出现 0 次）；`crops` 的个数等于这两类片段数，`at` 按片段顺序不减、在 `[0, markdown.length]` 内，且落在可插入行内节点的位置（不在代码、链接目标或公式内部）；`renderMarkdown(markdown, 'translation')` 不得出现 `html_blocked` 节点。任一不过 → `failed`（`math_mismatch` / `crop_position` / `html_leak`）。
5. 通过 → `success`，写入 `markdown`，`check.result = 'passed'`。存储与读出逐字节一致（AC-48）。

**状态与显示版本**（`block-status.ts`、`adopted-version.ts`）：

- 重译时先写一条新版本 `retranslating`，旧的 `success` 版本照常显示；新版本结束后转为 `success` 或 `failed`。状态转移只在 core。同一块已有 `retranslating` 版本时，`retranslateBlock` 返回 `already_retranslating`，不排第二个任务。
- `retranslateBlock` 的 `Result` 只表示受理与否。每次状态转移后 core 发 `translation.onBlockChanged`（`{ documentId, revisionId, sourceBlockId, status, version, failureKind }`，普通数据）；UI 收到后用 `getBlocks({ sourceBlockIds: [id] })` 取该块。UI 不根据调用返回、计时或任务事件推断块状态（RULES §5 第 13 项）。
- 显示规则（`adopted-version.ts`）：有 `success` 版本就显示最新的 `success`；没有时显示最新版本。`failed` 显示原文，状态行按 `failureKind`：`check_failed`「未翻译（校验没过）· 重译」、`network`「未翻译（网络问题）· 重译」、`model_error`「未翻译（模型出错）· 重译」；`failureKind` 为 `null` 时用「未翻译 · 重译」。`retranslating` 显示骨架。
- 重译失败（最新版本 `failed`，但还有更早的 `success`）时的界面，按 Wisdom 2026-10-30 22:02（PRD AC-56，DESIGN §4.1，对应 MD-27）：
  - 正文照常显示上一版 `success`；块左侧 2px 标记线，颜色用 `--oi-reader-warn`。块末提示行按 `failureKind`：`check_failed`「重译未成功（校验没过），仍显示上一版 · 重试」、`network`「重译未成功（网络问题），仍显示上一版 · 重试」、`model_error`「重译未成功（模型出错），仍显示上一版 · 重试」。`failureKind` 为 `null`（core 不应在失败时给出）时用「重译未成功，仍显示上一版 · 重试」。
  - 「重试」是次级文字按钮，调 `retranslateBlock`。悬停或键盘聚焦状态行时显示该原因的详情（DESIGN §4.1）：`check_failed`「新译文里的公式、数字或引用编号和原文对不上，已丢弃。可以再试一次。」、`network`「没连上翻译服务或超时。请检查网络后重试。」、`model_error`「翻译服务返回了错误或看不懂的结果。可以重试，或到设置 › 模型来源 换一个翻译服务 / 改选本地。」、`null` 无详情。
  - 不弹 toast、弹窗或全局横幅。
  - 重试期间提示行显示「正在重译…」，「重试」禁用；成功后标记线与提示行消失，显示新版本；再次失败回到上面的样子。
  - 从未成功的块：显示原文 + 2px 标记线 + 按 `failureKind` 的提示行「未翻译（校验没过）· 重译」「未翻译（网络问题）· 重译」「未翻译（模型出错）· 重译」；`null` 用「未翻译 · 重译」。悬停或聚焦显示上一条的详情。
  - 无障碍：提示行 `role="status"`；「重试」可用键盘聚焦，焦点环用 `--oi-reader-focus`；状态不只靠颜色区分（标记线之外还有提示文字）。两个 Token 由 Loom 定义（DESIGN.md §3.3、§3.4：`--oi-reader-warn`、`--oi-reader-focus`；色值待审批）。
  - 以上是 reader UI 的样式；「显示哪个版本、要不要失败提示」由 core 判定：`getBlocks` 每块返回 `display`（`current` 正常、`retranslating` 显示上一版并提示「正在重译…」、`previous_with_failure` 重译失败仍显示上一版、`never_succeeded` 从未成功、`pending` 没有可显示的版本且正在翻译，显示骨架），UI 只按 `display` 选样式、只按 `failureKind` 选文案。

**缓存键**（`cache-key.ts`）= 下列字段规范化后的 SHA-256：

| 字段 | 为什么在键里 |
| --- | --- |
| `formatVersion`（`oi-md/1`） | 方言变了，旧正文不能直接用 |
| 占位协议版本与公式切块版本 | v1 事故教训：缺这两项会显示旧公式（v1 审查 §4.18） |
| 原文区块占位文本的哈希 | 原文变了就重译 |
| 区块类型 `blockKind` | 规格补充：标题、列表项等的提示词或还原可能不同；重解析把段落改判为列表项时不能复用 |
| 公式决定摘要 `formulaDigest` | 取代原先键里的「受保护片段表哈希」。片段表哈希只覆盖 LaTeX 字符串，覆盖不了「LaTeX 不变、写法变了」（LaTeX 与裁图之间）这类变化，论证见[差异清单](./docs/v2-gap-and-changes.md) §6.2.1 |
| `providerId`、`modelId`、目标语言 | 换模型或语言就重译 |
| 提示词模板版本、润色开关 | 翻译方式变了就重译 |
| 术语摘要 | 本块命中的术语表条目进了提示词（§7.11）；没有命中时是固定值 |

`formulaDigest` = 本块受保护片段按出现顺序规范化后的 SHA-256。每个片段取「还原时实际写进 `markdown` 或决定显示方式」的全部内容：

- 公式片段：行内 / 行间；写法（`latex`、`crop` 或 `page_link`，由当前采用版本的显示决定得出：`verified-latex`、`source-checked-latex` 与 `format-checked-latex` 都是 `latex`，`source-crop` 是 `crop`，`page-placeholder` 是 `page_link`）；`latex` 时为规范化后的 LaTeX 字节，`crop` 时为裁图资产的内容哈希，`page_link` 时为页码。
- 编号、引用片段：原文字节。
- 另含占位协议版本与公式切块版本。
- **不含** `decisionId`、候选 ID、候选来源、评分与评估器版本、`revisionId`，也不含「是否已核验」（`verified-latex`、`source-checked-latex` 与 `format-checked-latex` 之别、`source-check-standing` 的结论）：它们变了而上面各项不变时，写进 `markdown` 的字节不变，放进来只会让重解析白白重译。所以「源码核对」翻转为已核验（§7.5），或用户「为本文评分」后同一 LaTeX 变为 `verified-latex`，都不触发重译（PRD AC-57 ⑨）；从 LaTeX 变为裁图或占位框、或裁图与占位框互变时写法变了，照常重译。

规则：

- **进提示词的每一项都要进键。** v2 的提示词只含本块占位文本、区块类型、命中的术语（v2 装配下为空）、提示词模板与润色开关；以后加入上下文段落时，必须同时加进键，并补 AC-57 的用例。
- **提示词正文只在一处。** `packages/features/translation/src/domain/prompts/`，一个模板一个文件，文件头写版本（如 `promptVersion`）。改模板正文必须升版本，旧缓存因此失效：版本变化则不读旧译文（缓存测试）。模型 id 只来自注册表，不写进模板文件名以外的第二处。
- 键里**不含** `documentId`、`revisionId`、`sourceBlockId`：重解析后内容不变的块、或另一篇内容相同的块，命中缓存直接复用，不发请求（AC-02）。记录本身仍绑定（文献, 采用版本, 区块）。
- 公式决定只随新的采用版本变化，不原地修改（§8.2 乐观锁）；`reevaluate-pending` 补评、`ingest.scoreDocument`（「为本文评分」）评分后显示决定若有变化，也要生成新的采用版本。规格补充。
- 读取兜底：`getBlocks` 把记录上的 `formulaDigest` 与当前采用版本算出的摘要比对；不一致时不返回旧正文（该块按 `pending` 显示），并自动排队重译。正常情况下不会触发，触发即记诊断事件。
- 在途结果：翻译请求按发出时的输入算键；结果回来时该块所属的采用版本已被替换，就只写缓存、不写 `tr_blocks`（与 §8.2「过期任务结果不能覆盖新版本」一致）。
- 只有 `success` 结果进入可复用缓存；`failed` 不缓存。`retranslateBlock` 不读缓存，一定重新请求，成功后覆盖同键的缓存条目（§7.11，PRD AC-73）。
- 裁图公式（`source-crop`）与占位框（`page-placeholder`）在译文中的表示已定（见上文）：`markdown` 不含它们，`crops` 记位置与 `kind`，`getBlocks` 生成节点。`crops` 由 `markdown` 与片段表确定，不单独进键。
- **公式标记（Wisdom 2026-10-30 22:15、22:23）**：`getBlocks` 给每块写成 LaTeX 的公式片段一个标记 `verified`、`source_checked` 或 `format_checked`（`TranslationBlockView` 的普通数据，按 `fragmentId` 对应）。`source_checked` 由 `formula/domain/source-check-standing.ts` 的结论在读取时算出；`format-checked-latex` 固定是 `format_checked`。标记不存进 `tr_blocks`，不进 `markdown`，也不进缓存键。reader 只按标记选徽标（「已核验」「源码核对」或「格式已核对」，样式待 Loom；「格式已核对」的视觉处理待 Loom，本规格不写颜色、位置或图标），不自己判断。

**存储**：SQLite，前缀 `tr_`，只有 `translation` 的 adapters 读写。

| 表 | 主键 | 内容 |
