## 1. 已确认范围与设计边界

- 桌面使用 Electron + TypeScript + React；首版 Windows / macOS。
- 面向 8 GB 内存核显电脑、M1 8 GB；默认远程重解析，可选本地服务。
- 双引擎固定为 A：Paddle 模块化；B：MiniCPM-OCR 对比与兜底。多模态仅补充低分区域。
- 首版支持用户自填 API / 自建服务；账号同步和手机派任务先定接口，不在首版承诺上线。
- 未来 Android / iOS 共用同账号，支持论文、阅读进度、批注、对话和手机派任务。
- 同步按论文开启；允许同步原 PDF 与结构化内容；密钥不同步。
- 语音先做朗读、讲解、语音转笔记；实时语音后续接入。
- 唯一新实现目标为 `https://github.com/wisdom-km/open-immerse-v2`；旧 [旧仓库参考快照](https://github.com/wisdom-km/open-immerse/blob/e9e00e47481d566188f73e5cbbd0c9a90463207d) 完全只读，新产品不含 extension 目录或扩展运行时依赖。
- 产品范围为 PDF 阅读/翻译、文献库、笔记、文本问答及基础语音；PDF 核心闭环后，以独立写作模块提供带引用草稿和 Markdown / LaTeX 导出，数据域与模块边界支持继续扩展。
- 自动补救由用户设置开关和预算策略控制；预算支持 `limited` 与 `uncapped`。达到上限时保留原图、提示复核；多模态仍不过时也显示原图。具体质量阈值后续定标，已确认的政策不再作为阻塞问题。

8 GB 设备不能默认同时加载两套重模型。数据协议必须与执行位置无关：同一输入由本机或远程执行，得到相同的可校验结果结构；性能和正确率需用真实设备另测。

## 3. 权威数据：JSON 文档模型，Markdown 为导出投影

结构化 Markdown + LaTeX 是两引擎统一的可消费输出，但 Markdown 字符串不能单独承载 bbox、来源、置信度、笔记锚点和版本。

推荐引擎先输出统一 JSON / AST，统一导出器生成 Markdown + LaTeX；导出包同时包含 `document.json`、`source.pdf`（按选项）、`assets/` 与 `readout.md`。普通 Markdown 导出只保证阅读，不承诺重新导入后恢复完整工作区。

```text
Document（按原 PDF 的 SHA-256 识别）
├── SourceFile（原文件，不改写）
├── ParseRun A / B / 历史运行（独立保留）
│   └── PageCandidate[]（候选块、公式、顺序、质量）
├── AcceptedPageRevision[]（每页当前采用版本）
│   ├── canonical blocks + order + provenance
│   └── translations（绑定该页版本与源文本哈希）
├── Notes / Annotations / Conversations
├── ReadingProgress / AudioAnchors
└── SyncPolicy（论文级开关）
```

数据库可以分表，但“该页当前采用的版面、块号、顺序、译文”只能通过一个带版本的聚合记录读取，不能由 UI 临时拼接多套来源。

## 4. proposed 类型示例

以下只展示关键字段；落地前补齐 JSON Schema、错误码与示例夹具，再生成 TypeScript 和服务端校验类型。

```ts
type Rect4 = [number, number, number, number]; // 仅四元组形状，不定义单位
type NormalizedBBox = Rect4 & { readonly __space: 'normalized-rotated-page' };
type PdfRectPt = Rect4 & { readonly __space: 'pdf-points' };
// branded 类型由校验构造器创建；运行时 JSON 仍是四个数，不序列化 __space。
type BlockKind = 'title' | 'heading' | 'text' | 'caption' | 'formula'
  | 'figure' | 'table' | 'header' | 'footer' | 'aside' | 'footnote';
type TextSource = 'pdf-text-layer' | 'ocr' | 'manual';

interface SourceRef {
  documentHash: string; pageNumber: number; // pageNumber 从 1 开始
  bbox: NormalizedBBox; textItemIds?: string[]; sourceId?: string;
  sourceText?: string; sourceTextHash?: string;
}
interface ContentBlock {
  blockId: string; kind: BlockKind; source: SourceRef;
  orderIndex: number; // 从 0 开始，仅在当前页版本内解释
  text?: { value: string; source: TextSource; trusted: boolean };
  inlineOf?: string; captionFor?: string; skipTranslate?: boolean;
  placeholders?: { token: string; formulaBlockId: string }[];
  groupId?: string; // 跨页续段；不替代每页原始块
  visual?: { cropAssetId: string; formulaDecisionId?: string };
}
interface AcceptedPageRevision {
  protocol: 'oi-document/2'; schemaVersion: 2; // 名称待定
  documentHash: string; pageNumber: number; revisionId: string;
  parentRevisionId?: string; parseRunId: string; coordinateFrameId: string;
  state: 'accepted' | 'fallback' | 'not-started'; fallbackReason?: string;
  blocks: ContentBlock[]; readingOrder: string[];
  translations: TranslationRecord[]; sourceAudit: SourceAudit;
}
interface TranslationRecord {
  translationId: string; blockId: string; pageRevisionId: string;
  sourceTextHash: string; text: string; targetLanguage: string;
  status: 'pending' | 'running' | 'completed' | 'failed' | 'needs-review';
  providerId: string; modelId: string; promptVersion: string;
  glossaryVersion?: string; protectedContentHash: string;
}
interface SourceAudit {
  items: { itemId: string; disposition: 'body' | 'visual' | 'excluded';
    blockId?: string; reason?: string }[];
  missing: string[]; duplicates: string[];
}
```

`blockId` 与 `revisionId` 的生成算法是协议的一部分，不能由 UI 重渲染临时生成。推荐每个采用版本生成不可变块 ID；同一页采用版本重开时复用原 ID。候选页不冒用已采用块号。

`readingOrder` 是显式块 ID 序列；`blocks` 导出的顺序必须与其一致，两者不符时拒绝提交。行内公式由正文占位符定位，不再重复输出成独立段落。页眉页脚可留在审计数据，主通读投影排除。

## 5. 坐标合同与 PyMuPDF / PDF.js 互通

规范坐标系：**原 PDF 当前页 CropBox 经页面旋转后的可见画面，左上原点、x 向右、y 向下**。`bbox=[x0,y0,x1,y1]` 均在 0–1，且 `x0<x1`、`y0<y1`。

每页记录以下坐标元数据：

```ts
interface CoordinateFrame {
  frameId: string; pageNumber: number;
  mediaBoxPt: PdfRectPt; cropBoxPt: PdfRectPt; rotationDeg: 0 | 90 | 180 | 270;
  displayWidthPt: number; displayHeightPt: number;
  rasterWidthPx: number; rasterHeightPx: number; dpi: number;
  pdfToRaster: [number, number, number, number, number, number];
  rasterToPdf: [number, number, number, number, number, number];
  renderer: { name: string; version: string }; imageHash: string;
}
```

实施步骤：

1. 预处理器读取 MediaBox、CropBox、旋转，建立规范 frame；传给模型的图片与该 frame 的 `imageHash` 绑定。
2. 厂商像素坐标先转换成该图片坐标，再除以宽高；厂商 0–1000、PDF 点坐标等仅允许在专用 adapter 内换算。
3. PDF 文字层提取器使用其实际坐标到规范 frame 的矩阵；不能直接照搬旧 `transform[5]/pageHeight` 或手动猜 y 翻转。
4. UI 用 PDF.js viewport 的真实变换，将规范 bbox 映射回当前 zoom / devicePixelRatio 的画面；不拿浏览器 CSS 像素作为持久化坐标。
5. 裁图依 `imageHash + bbox + cropPolicyVersion` 生成；高分辨率重渲染时仍使用同一规范 frame。

PyMuPDF 与 PDF.js 的坐标约定不能假定相同。需要明确验证两个库具体 API 的旋转和裁剪处理，保存实际矩阵；重新渲染只改光栅尺寸，不改 bbox 语义。六元矩阵顺序固定为 `[a,b,c,d,e,f]`，映射 `x'=ax+cy+e, y'=bx+dy+f`，不能混用不同库的参数排列。

约 300 DPI 图像是解析 worker 的按页输入，不是桌面 UI 整篇常驻资源。桌面 PDF.js 按可见页虚拟渲染、限制预取页数与并发、及时释放 canvas；worker 也按有界队列处理并释放 page raster。8 GB 目标设备的内存预算与逐页延迟必须真机测量。

必须覆盖 0/90/180/270 度、非零 CropBox、MediaBox 大于 CropBox、双栏、跨栏、页面缩放及不同 DPI。选 144/300 DPI 时同一物理区域应点击和裁图一致；误差阈值需在真实样本上定标。

## 6. 公式：候选、采用结果、展示方式分开

**已确认：无法验证的公式显示原页裁图，同时保存候选 LaTeX，供对比、纠错与未来重跑；对不确定公式必须支持多模态核验。**

```ts
type EvaluationResult = {
  evaluatorId: string; evaluatorVersion: string; providerVerdict?: string;
} & (
  | { status: 'scored'; rawScore: number; calibratedScore?: number; reasons: string[] }
  | { status: 'error' | 'unavailable' | 'not-run'; rawScore?: never;
      calibratedScore?: never; reasons: string[]; errorCode?: string }
);
interface FormulaCandidate {
  candidateId: string; blockId: string; parseRunId: string;
  latex: string; engineId: 'paddle-modular' | 'minicpm-pipeline' | 'multimodal-repair';
  modelVersion: string; rawResponseAssetId?: string;
  evaluation: EvaluationResult;
  validation: { syntax: 'pass' | 'fail'; evidence: string[];
    sourceMatch: 'pass' | 'fail' | 'unverifiable' };
}
interface FormulaDecision {
  decisionId: string; blockId: string; candidateIds: string[];
  acceptedCandidateId?: string; sourceCropAssetId: string;
  display: 'verified-latex' | 'source-crop';
  decisionReason: string; policyVersion: string;
}
```

LaTeX 语法可渲染只说明语法成立，不证明公式正确。Jev 的原始分值必须连同 evaluator 版本保存，不能直接解释成“正确概率”。只有 `status: scored` 有有效分值；服务失败、未配置、未运行不能伪装成 0 分或触发“内容低分”路由。厂商更细的 verdict 原样记入 `providerVerdict`，adapter 再映射为规范状态。依据目标样本校准阈值，并结合 PDF 字符、数字、公式编号、原图对照和人工修正记录。

双引擎都产出候选，统一仲裁层才决定采用。分支 B 只给 Markdown、没有可靠位置时，只能作为文档级候选或需复核结果，不能伪造 bbox 后进入可点击阅读器。

FormulaCandidate.blockId 属于其 parseRunId 的候选页命名空间；FormulaDecision.blockId 属于采用页版本。采用时显式保存候选块到采用块的映射，不能因为两个运行内块号相同就当作同一个公式。

核验流程固定为：专用引擎候选 → 质量/来源检查 → 仅低分或不确定公式进入多模态核验 → 再验证 → 通过才采用 LaTeX；失败、超时、无可用服务或仍无法核验时使用原图。多模态核验接口接受目标公式裁片、必要的局部上下文和候选，返回核验结论及可选修正候选；不扩展为整篇多模态解析，也不让它直接翻译公式。模型自行声明“正确”不能替代来源核对。用户未配置可用多模态服务时保留 `unverifiable` 状态与原因。

自动补救设置独立保存 `autoRepairEnabled`、允许的补救动作、预算模式与预算周期。`limited` 的金额限额带币种；没有可靠计价信息时可另设调用次数/token 预算并明确其不是精确金额保证。`uncapped` 表示用户不设金额预算上限，仍受有限的每区域尝试次数、超时、并发和服务限流约束。任务记录策略快照、已预留与已结算费用；到上限时停止自动调用，公式保留原图与候选并提示复核，不静默切到另一付费服务。手动继续需更新有效策略或预算，不能只改 UI 状态绕过任务层检查。

公式识别结果不会进入自然语言翻译。图和表仍保存原图证据；表结构、单元格候选与显示原图可共存，但未经验证的表内容不得静默替换原数据。

若保留 arXiv 源码校准能力，新增独立候选来源类型，并继续逐公式与当前 PDF 核对；是否保留其产品入口待定，不把历史七级调度直接移植回来。

## 7. 翻译必须可验证地保护 LaTeX

推荐翻译流程：块自然语言 → 抽出公式和其他受保护片段 → 不透明占位符 → LLM → 验证 → 恢复采用公式 → 阅读与导出。

- 延续旧 `⟦fN⟧` 的完整性检查；新协议同时用独立片段表保存公式原始字节和哈希。
- 译文不得改变公式数量、关联对象与序列；引用编号、数字、变量需单独检查。不要只靠系统提示词。
- 两步润色、重译、流式输出都经过同一检查。流式片段先标临时，完整性通过才落成 `completed`。
- 公式保护哈希绑定 `pageRevisionId + blockId + formulaDecisionId`，防止重跑后旧公式和新译文混配。
- 检查失败时记录 typed error、保留原文并显示待复核；允许有限重试，不把公式统一挂到句末补救。
- 缓存键包含源文本哈希、采用版本、目标语言、模型、提示词、术语表和润色策略版本；记录不能包含密钥。

“LLM 强制保留 LaTeX”由上述外部机制落实。若实现选择把 LaTeX 原样发送给模型，响应仍须逐片段字节或规范化哈希核对；不能仅判断 `$` 是否闭合。

## 8. 双引擎运行、采用版本与页级重跑

`ParseRun` 记录引擎、模型/权重版本、配置指纹、执行位置、输入 PDF / 图像哈希、开始结束状态和错误原因。A/B 各有独立记录，不覆盖彼此。

用户切换引擎有两种动作，接口必须区分：`compare` 只新增候选；`adopt` 才更新页采用版本。默认采用 A 的合格结果；B 的补充和替换必须有来源与仲裁原因。

采用操作用事务比较旧 `revisionId`，写入新块、顺序、公式决策和待翻译记录，随后原子切换 current 指针；失败保持旧版可读。长任务回调必须带 job / run / revision 身份，过期响应不覆盖新页。

版面或源文本变化时，只使该页受影响译文失效。纯展示缩放、重新生成光栅、模型名称配置变化不自动销毁已采用结果；明确“重跑并采用”才改变页面版本。

## 9. 笔记、对话、语音的统一锚点

```ts
interface ContentAnchor {
  documentHash: string; pageNumber: number; pageRevisionId: string;
  blockId?: string; bbox?: NormalizedBBox;
  quote?: { exact: string; prefix?: string; suffix?: string };
  sourceTextHash?: string; groupId?: string; memberBlockIds?: string[];
}
```

笔记正文独立于版面生命周期保存。切换页版本后按旧块身份、文字项来源、引用文本与位置组合寻找锚点；唯一高置信匹配才重锚。多候选或找不到时标为 `needs-reanchor`，保留原页、原引文与旧位置，不能删笔记或强行挂到相似块。

对话引用同一锚点；音频章节和讲解保存脚本版本与锚点；阅读进度同时保存页码、块号及页内偏移。语音转笔记保存原转写、用户修订和创建来源，不把转写当 PDF 原文。

## 10. 旧 blocks-1 迁移与兼容

旧 `lib/pdf-blocks.js` 的 `normalizeIncomingBlock()` 会删除视觉块 `latex/content/html/md/text`。新候选必须进入独立的 `FormulaCandidate`，采用结果进入 `FormulaDecision`；不得把它们塞进旧视觉块后期待旧清洗器保留。

兼容视图只负责把新模型投影为旧 `blocks-1` 可读的原图块、自然语言块及占位符，`formulaDecisionId` 在新规范侧解析；这条投影不携带未经验证的公式字母。新 renderer 直接读新规范，不能依赖旧清洗函数理解新字段。旧格式导入与兼容导出要分别测试，避免 adapter 双向处理时丢失候选。

| 旧字段/行为 | 新记录与迁移规则 |
|---|---|
| `protocol: blocks-1` | 仅导入 adapter 接受；输出新协议显式带 schemaVersion |
| `page`、归一化 `bbox` | 保留；确认原旋转/光栅参照后生成 coordinateFrame，未知时标待核查 |
| `id` / 已有 `bid` | 保存 legacyIds；在旧页版本内建立映射，不用临时 ID 当跨版本主键 |
| `sourceId`、`sourceText` | 原样保留；补哈希和 provenance，不能重新 OCR 覆盖来源 |
| `textSource` 页级字段 | 映射到块的来源；同页混合文字层/OCR 时逐块记录 |
| `inlineOf`、`placeholders`、`captionFor` | 完整转换引用；引用缺失时报告错误，不静默丢公式 |
| `pairs[].translation` | 文件哈希、来源身份、原句及占位符一致才恢复为有效译文 |
| 图片式公式与已有核验 LaTeX | 保留原图证据；分别映射 crop 和候选/采用结果，不绕过核验 |
| `groupId`、`memberBids` | 保留跨页组关联；原块不合并删除 |
| 旧整篇 `readout.md` | 只作兼容导入/查看；无逐页证据时不得伪装恢复精确锚点 |
| 旧密钥 | 不导出、不导入、不同步；新桌面安全存储由用户重新填写 |

迁移器先 dry-run 出报告，再在新目录/新数据库事务中导入；以文件哈希、迁移版本和原记录身份保证重复导入幂等。原导出包不改写。遇到未知未来 schema 整包拒绝并提示升级；可恢复的旧版本用明确 migrations 链逐版处理。

## 11. 同步 canonical 数据与缓存的区别

论文默认按用户选择决定同步开关。开关开启后可同步原 PDF、采用页版本、采用块/顺序/公式决策、已完成译文、进度、批注、对话及其引用；二进制走对象存储引用与内容哈希，元数据走版本接口。

可再生成的模型输入光栅、临时 crop、失败请求响应、权重和中间候选不默认同步。已采用结果依赖的原图证据必须能由同步的 PDF + frame + bbox 重建，或作为采用资产上传；不能把必要定位数据误归为“版面缓存”而丢掉。

同步版本包含 entityId、revision、deviceId、updatedAt 和 tombstone；离线重试用幂等 mutationId。不可变页版本可并存，current 指针竞争需冲突处理；笔记内容并发修改保留冲突副本或使用明确合并策略，不能仅按客户端时钟覆盖。

手机派任务只提交论文身份、页范围、参数、期望源版本和执行目标；结果仍返回同一协议。账号与任务接口首版只定义，不将 localhost 服务暴露为公网账号服务。API key 保留在执行端的 SecretStore，任务/同步体只传 credentialRef，不传密钥。

桌面离线时，手机派发的重任务可由该账号已配置且可用的远程服务执行；没有可用服务或预算时进入明确等待状态（如 `waiting-for-executor` / `waiting-for-budget`），等待服务恢复、桌面上线或预算调整。任务等待不改变已采用页面；公式区域因预算到限暂不能继续核验时，阅读页仍使用原图并显示复核提示。

## 13. 契约验收与实际验证边界

以下是待实施的验收清单，尚未执行，不构成当前测试通过声明。

1. Schema：合法样例通过；越界 bbox、重复 blockId、悬空引用、缺失 frame、未知未来版本拒绝。
2. 坐标：旋转/裁剪/DPI 组合下 PyMuPDF crop 与 PDF.js 高亮为同一区域；无邻行误切。
3. A/B：同份 PDF 两分支都给可追溯结构，Markdown 导出不丢原块对应；缺 bbox 明确降级。
4. 文本：可信文字层原句不被 OCR 改写；每文字项有归属，missing/duplicates 为空或明确失败。
5. 公式：候选保存与采用分离；仅语法通过/仅 Jev 高分不能直接标 verified；不确定区域能做多模态核验，仍不过显示原图，候选保留。Jev 非 scored 状态无分值；自动补救开关和 limited/uncapped 策略正确，到上限停止自动调用并提示复核。
6. 翻译：故意删/换/调序公式、改引用与数字的响应被拒绝；两步润色同样检查。
7. 版本：对比不改阅读页；采用原子切换；取消后旧任务结果不能覆盖；仅受影响页失效。
8. 锚点：重跑不删笔记；歧义重锚可见；对话和语音链接回同一原文区域。
9. 迁移：旧逐页 pairs 优先、重复导入幂等、未知版本失败无半包、原件与密钥边界正确。
10. 同步：论文关同步不上传；启用后跨端可定位；无密钥；断网重试和并发修改不静默丢数据。桌面离线可派发到可用远程服务，无服务/预算时任务等待，已有阅读页可用。
11. 重开：采用版本、块号、类别、顺序、译文与上次关闭一致；回退页可读且记录原因。
12. 真实样本：数字/扫描/混合页、双栏/跨栏、复杂公式/表格分别统计；自动夹具通过不代替实际模型与桌面视觉验收。

建议先把上述 1–9 做成引擎与存储的契约门槛，再接桌面。10 在同步实现阶段执行，11–12 在目标 Windows/macOS 真机执行；不因接口已预留而宣称手机、云服务或语音模型已可用。
