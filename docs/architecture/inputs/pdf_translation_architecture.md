# 英文学术论文 PDF 翻译项目技术架构方案

## 项目目标
将英文学术论文 PDF 翻译为中文，支持单栏 / 双栏 / 复杂版面，公式保留 LaTeX 格式，最终输出结构化 Markdown。  
项目需同时支持两套技术路线（百度模块化方案 + MiniCPM 端到端方案），便于实际对比测试后选择主力方案。

## 整体技术架构（树形双分支）

```
                        输入层
                    PDF 预处理
              （PyMuPDF：文字层检测 + 页面渲染）
                           │
              ┌────────────┴────────────┐
              │                         │
        分支A：百度模块化          分支B：MiniCPM 端到端
              │                         │
    PP-DocLayout + PP-FormulaNet   MiniCPM-OCR 1.0
    + 自写阅读顺序算法              （含版面 + 阅读顺序
              │                    + 公式 + 表格）
              │                         │
              └────────────┬────────────┘
                           │
                     统一输出层
               （结构化 Markdown + LaTeX）
                           │
                     质量评估层
                  （MiniCPM-OCR Jev）
                           │
                  ┌────────┴────────┐
                  │                 │
               翻译层            多模态补充层
            （LLM 主力）        （仅低分区域兜底）
                  │                 │
                  └────────┬────────┘
                           │
                        最终输出
```

## 详细流程说明

### 1. 输入层（公共）
- 使用 PyMuPDF 打开 PDF。
- 检测每一页是否有可提取的文字层。
- 将每一页渲染成 300 DPI 左右的图片，供版面模型和识别模型使用。

### 2. 分支A：百度模块化方案（主力）
- **版面分析**：PP-DocLayout-L 或 PP-DocLayoutV3  
  输出边界框 + 类别（text、formula、inline_formula、table、figure、title 等）。
- **公式识别**：PP-FormulaNet-L / PP-FormulaNet_plus-L  
  裁剪公式区域后转成 LaTeX。
- **文本提取**：PDF 文字层优先对齐，失败时用 PaddleOCR 兜底。
- **表格**：可选使用 PaddleOCR 表格模块转成 Markdown。
- **阅读顺序**：自己写算法（借鉴 MinerU 的几何规则思路）  
  - 判断单栏 / 双栏  
  - 跨栏元素优先处理  
  - 左栏 → 右栏排序  
  - 填充内容后组装成 Markdown。

### 3. 分支B：MiniCPM 端到端方案（对比 + 兜底）
- 使用 **MiniCPM-OCR 1.0** 直接对页面图片做端到端解析。
- 输出已包含阅读顺序的结构化 Markdown（公式为 LaTeX，表格已处理）。
- 内部使用 PP-DocLayoutV3 做版面检测。
- 开发量小，适合快速对比和复杂版面兜底。

### 4. 统一输出层（公共）
- 两个分支都输出相同格式的结构化 Markdown（公式为 LaTeX）。
- 方便后续统一处理和对比。

### 5. 质量评估层（公共，强烈建议）
- 接入 **MiniCPM-OCR Jev**。
- 对每个区域的识别结果打分（0~1）。
- 低分区域标记出来，供后续处理。

### 6. 翻译层 + 多模态补充层
- **翻译主力**：大语言模型  
  只翻译自然语言文本，**强制保留 LaTeX 公式**，保持 Markdown 结构。
- **多模态位置**：放在翻译层之前或并行，**仅作为补充兜底**  
  - 对 Jev 打分低的区域，再丢给多模态模型重新识别或理解。  
  - **不要**让多模态同时扛版面分析、公式识别和翻译。  
  - 只处理“专用小模型 + Jev 判断有问题”的少数区域。

### 7. 最终输出
- 中文 Markdown，公式仍为 LaTeX。

## 两套方案对比

| 维度 | 百度模块化方案 | MiniCPM 端到端方案 |
|------|----------------|-------------------|
| 版面分析 | PP-DocLayout | 内部 PP-DocLayoutV3 |
| 公式 | PP-FormulaNet | 模型内置 |
| 阅读顺序 | 自己写 | 模型直接输出 |
| 开发成本 | 较高 | 低 |
| 可控性 | 高 | 中 |
| 复杂版面 | 依赖规则优化 | 开箱较好 |
| 推荐用途 | 主力 | 对比 + 兜底 |

## 项目实现建议
1. **引擎抽象**：定义统一接口，两个分支分别实现。
2. **配置切换**：通过配置选择当前使用的分支。
3. **对比测试**：同一份 PDF 同时跑两个方案，对比输出。
4. **质检统一**：两套方案都接入 Jev。
5. **多模态按需启用**：默认关闭，只在低分区域开启。

## 总结
本方案以百度模块化方案为主力（可控性高，适合自己优化阅读顺序），以 MiniCPM 端到端方案作为对比和兜底。通过统一接口和配置，实现双方案并行支持。多模态模型仅作为低分区域的补充，不参与主力流程。
