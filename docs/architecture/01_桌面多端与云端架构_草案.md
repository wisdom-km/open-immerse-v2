日期：2026-10-30。状态：设计草案，供需求对齐和后续技术评审。
本次仅新增设计文档，未修改 D 盘项目源码，未运行模型、迁移数据库或验证桌面应用。
下文新增目录、类型、API 和任务状态均为拟议设计，不表示现有仓库已经实现。
目标为独立新仓库 [wisdom-km/open-immerse-v2](https://github.com/wisdom-km/open-immerse-v2)；旧仓库保持原样，仅用于参考与选择性移植。
新产品只有桌面、共享核心、服务和未来手机端，不设置 extension 目录，不保留浏览器功能。

## 1. 已确认边界与尚未决定的事项

| 类别 | 当前对齐结果 |
| --- | --- |
| 桌面技术栈 | Electron + TypeScript + React，首版 Windows / macOS。 |
| 最低设备 | Windows 8GB 内存、核显；Mac M1 8GB；通过远程解析/OCR/模型服务也应能完整使用。 |
| 本地基础能力 | PDF.js 渲染、文字层读取、原页高清裁图、本地文献库与缓存。 |
| 解析路径 | Paddle 模块化主力、MiniCPM 对比与兜底；推理能力与应用服务分开。 |
| 首版远程能力 | 用户自填 API / 自建服务；翻译 API 与解析 API 分别适配。 |
| 后续多端 | iPhone / Android；同账号同步论文、进度、批注、对话，手机可派解析任务。 |
| 多端上线顺序 | 账号同步与手机派任务先定义接口，后续上线；官方收费云仅留入口。 |
| 同步与上传 | 按论文启用同步，允许上传原 PDF 和结构化结果；密钥不随同步传递。 |
| 语音 | 先朗读讲解和语音转笔记，实时语音问答后续接入。 |
| 临时资产 | 定期清理；清理周期、失败任务保留期与用户配置方式仍待确认。 |
| 首版功能 | PDF 阅读、翻译、文献库、笔记、文本问答与基础语音。 |
| 写作辅助 | PDF 核心完成后独立实现带引用的大纲/段落草稿和 Markdown / LaTeX 导出；完整编辑器与编译后置。 |
| 低分区域补救 | 用户设置启用开关、金额限额或不设金额上限；额度到达则原图 + 复核提示。 |
| 手机独立执行 | 桌面离线时可使用可用的远程服务独立完成；没有可用服务或预算时等待。 |

学习中心和非 PDF 文档翻译不纳入本轮实现范围；arXiv 源码校准入口作为后续可选候选，不自动继承旧调度。
旧文档的既定事项与本轮要求冲突时，以本轮确认结果为准；旧扩展既不删除，也不在本轮维护。

## 2. 为什么采用 TS 应用核心 + Python 推理 worker

现有 [providers.js](https://github.com/wisdom-km/open-immerse/blob/e9e00e47481d566188f73e5cbbd0c9a90463207d/lib/providers.js#L203) 已有统一网络调用；[pdf-blocks.js](https://github.com/wisdom-km/open-immerse/blob/e9e00e47481d566188f73e5cbbd0c9a90463207d/lib/pdf-blocks.js#L221) 已有译文完整性检查。
[library-store.js](https://github.com/wisdom-km/open-immerse/blob/e9e00e47481d566188f73e5cbbd0c9a90463207d/lib/library-store.js#L576) 已通过平台接口访问仓储，适合抽取行为契约。
保留这些规则并逐步迁成 TS，可减少把同一套来源校验、公式保护和导入行为在 Python 重写的成本。

Python 负责 PDF 预处理、版面、OCR、公式、阅读顺序、Jev 评估和指定区域修复等解析计算。
TS 负责文献用例、任务协调、结果验收与发布、翻译、同步、语音任务和 provider 配置。
跨语言共享版本化 JSON 协议与样例；不要维护两份人工独立修改的块字段定义。
这不要求所有旧 JS 一次性重写：先保持测试可运行，再按领域迁移，避免同时更换行为和语言。
本地模型始终是可选执行能力；未安装 Python/模型权重或没有独显，不应阻断完整产品流程。
解析能力可由云端电脑、自建远程解析服务、OCR API 等按协议适配；多模态 API 继续只补充低分区域。
8GB 设备应能完成本地阅读与编辑，并以已配置远程服务完成重计算；网络依赖与失败状态应在任务中明确显示。

## 3. 分层与进程职责

```text
React 桌面 UI                         未来手机 UI
    │ 受控 IPC                            │ HTTPS
Electron preload                     应用 HTTP API（后续）
    └───────────────┬─────────────────────┘
                 TS 应用用例
      导入 / 解析任务 / 翻译 / 文献库 / 同步 / 语音任务
                        │
                 TS 领域规则与端口
       来源身份 / 版本 / 块完整性 / 引用锚点 / 任务状态
         ┌──────────────┼─────────────────┐
     桌面适配器      用户远程服务适配器      云端适配器（后续）
     SQLite+文件      BYOK / 自建服务       PostgreSQL+对象存储
         │                   │                    │
     可选本地 worker     远程解析 worker        云解析 worker
                    Python 双方案引擎
```

Renderer 负责界面、PDF.js 页面渲染与按需裁图；大文档页面按需加载并释放非活动画布。
Electron main 负责文件选择、受控文件访问、凭据、窗口与生命周期；长任务不要阻塞 main。
应用用例可在 Node utility process 运行；首版也可由 main 装配，是否独立以实际负载验证决定。
preload 只暴露具体命令和订阅，不向 UI 暴露任意 SQL、文件路径读写、shell 或通用 IPC 对象。
Python worker 不直接写用户文献库，不决定当前文献版本，不拥有账号同步状态。

Electron 隔离、沙箱和 IPC sender 校验按 [官方安全文档](https://www.electronjs.org/docs/latest/tutorial/security) 落实；具体设置随锁定的 Electron 版本验证。

### 3.1 防止再次形成单文件应用

旧 `pdf/viewer.js` 本轮统计为 16,641 行；新仓库不能沿用一个入口同时管理渲染、网络、存储和任务的结构。
`renderer/entry` 与 `main/bootstrap` 只装配依赖和注册入口；具体流程进入用例，不在入口持续追加业务分支。
依赖方向为 UI / transport → application → domain；adapters 实现 ports，由 composition root 注入。
domain 禁止 import React、Electron、DOM、数据库驱动或厂商 SDK；application 禁止 import 具体适配器。
renderer 不直接访问 SQLite、SecretStore 或 Python 进程；也不以全局 store 旁路应用用例。
阅读页面按 document-session、page-view、translation-view、notes、qa、audio 等职责组织，状态就近归属。
document-session 只协调当前文献上下文，不持有所有面板的可变状态；持久任务由应用层管理。
共享包按稳定职责命名；禁止把不相关功能堆入万能 `utils`、`shared/state` 或循环调用的 services。
写作域通过文献查询和引用契约消费阅读产物；reader 不反向依赖 writing，也不直接调用写作 UI。

CI 静态检查跨层 import、循环依赖、renderer 越权 import 与新增 Chrome API；架构规则违规应失败。
文件超过约 400 有效代码行、函数超过约 80 行或圈复杂度超过约 15 时触发评审提示，数值是初始软门槛。
生成文件、协议样例与测试夹具单独统计；软门槛可解释豁免，不能通过机械切文件获得“架构合格”。
评审同时检查变更原因、职责数量、依赖扇出和测试隔离性；单文件行数下降不能代替这些证据。
模块边界测试验证可换 memory repository / fake executor 后运行用例，不启动 UI 或模型也能检查规则。

## 6. 应用端口与远程任务接口

下面类型仅描述职责，不是可直接调用的现有 SDK。

```ts
type ExecutionTarget = "local-basic" | "local-parser" | "user-remote" | "managed-cloud";
type JobKind = "parse" | "translate" | "explain-audio" | "transcribe-note";
interface JobExecutor {
  capabilities(): Promise<ExecutorCapabilities>;
  submit(command: JobCommand): Promise<JobReceipt>;
  get(jobId: string): Promise<JobSnapshot>;
  cancel(jobId: string): Promise<CancelReceipt>;
  events(jobId: string, after?: string): AsyncIterable<JobEvent>;
}
interface DocumentRepository {
  read(documentId: string): Promise<DocumentSnapshot>;
  publish(input: PublishVersionCommand): Promise<DocumentSnapshot>;
}
interface AssetStore {
  put(input: AssetInput): Promise<AssetRef>;
  open(ref: AssetRef): Promise<AssetStream>;
  remove(ref: AssetRef): Promise<void>;
}
interface TranslationProvider { translate(input: TranslationInput): Promise<TranslationResult> }
interface SecretStore { read(ref: string): Promise<SecretValue>; write(value: SecretValue): Promise<string> }
interface ProviderConfig {
  provider: string; baseUrl: string; model?: string;
  capabilities: string[]; secretRef?: string;
}
```

ProviderConfig 只描述厂商、地址、模型、能力与凭据引用；不夹带明文 key 或任意授权 header。
secretRef 由执行环境解析；配置同步副本剔除设备私有 secretRef，接收端重新绑定本机或其自建服务的凭据。
TranslationProvider、ASR、TTS、RealtimeVoice 分别有能力契约，不能用一个“通用模型调用”掩盖流式和音频差异。
本地、用户远程和未来官方服务是执行配置；业务逻辑不写死某个 SDK、地址或模型名称。
相同 TS 用例可分别经本地 IPC 和云端 HTTP 进入；HTTP 框架是可替换适配器，不是领域模型的一部分。

`capabilities` 声明引擎、版本、支持页数/格式、资产传输、取消与幂等能力；不假设第三方已有同名路由。
每个第三方服务通过适配器映射；只提供同步整篇 API 的服务也可包装成应用任务，但能力限制必须保留。
翻译的 OpenAI-compatible 服务不自动等于支持 Paddle/MiniCPM 解析的服务；配置页分别说明用途和检查项。

| 拟议应用 API | 职责与返回 |
| --- | --- |
| `POST /v1/assets/uploads` | 创建受限上传，返回 uploadId / 传输信息；不把大 PDF 放普通 JSON。 |
| `POST /v1/documents` | 绑定资产摘要和文献身份；重复导入行为由应用规则决定。 |
| `POST /v1/jobs` | 提交解析/翻译/音频任务，返回 202 + jobId。 |
| `GET /v1/jobs/{id}` | 返回阶段、已完成页、错误与可重试状态。 |
| `GET /v1/jobs/{id}/events` | SSE 事件；可断线后按游标补拉。 |
| `POST /v1/jobs/{id}/cancel` | 请求取消；区分已请求和远端已停止。 |
| `GET /v1/documents/{id}/versions/{version}` | 获取确定版本的结构化结果和资产引用。 |
| `POST /v1/sync/push`、`GET /v1/sync/pull` | 后续账号同步；实体版本、变更游标与冲突结果。 |

接口描述以共享 [OpenAPI 规范](https://spec.openapis.org/oas/latest.html) 为依据；落地时锁定工具链支持的版本，不依赖文档的 latest URL 固定行为。

## 7. 任务、来源和版本的一致性

任务至少携带 jobId、documentId、sourceHash、pageRange、engineId、配置摘要、协议版本、idempotencyKey。
worker 输出携带 parseRunId、模型/算法版本、页面坐标变换、来源证据、质量报告与结果资产清单。
状态建议为 queued → running → validating → completed；另有 waiting-service、waiting-budget、failed、cancel-requested、cancelled、unknown-outcome。
remote 超时不等于未执行；第三方不支持幂等时，不能无条件重发产生第二次费用。
UI 显示当前阶段和页数，无法估算的工作不生成假百分比；重开 App 仍能查询持久任务。
低分补救策略独立保存 enabled、额度模式、金额/币种/统计范围和执行目标，不借用模型配置猜测用户意图。
选择“不设金额上限”仅取消用户金额阈值；区域次数、超时、并发、技术重试和防循环仍有硬限制。
启用且额度可用时才自动补救；受限且额度到达时保留原图、候选和复核提示，不把低分结果当可信正文。
预算信息不足以判定剩余额度时保留待处理状态；并发任务需先预留预算再提交，结束后按可获得的实际用量结算。

A/B 运行结果独立保存，比较后才发布对应页的 AcceptedPageRevision，并更新文档聚合版本；失败结果不能覆盖已接受版本。页级权威类型以 02 文档为准。
发布时校验 sourceHash、页范围、块身份和版本；译文绑定解析版本、源文本摘要、语言与翻译配置摘要。
公式保护以程序验证占位符与 LaTeX 原文为准；模型提示词只是辅助，不是完整性保证。
应用用例是当前版本的唯一发布者；同步器、worker 和 UI 都不能各自选择另一份“当前版面”。

high-precision 的迁移先保留 [内容与坐标契约](https://github.com/wisdom-km/open-immerse/blob/e9e00e47481d566188f73e5cbbd0c9a90463207d/pdf/high-precision/ARCHITECTURE.md)、[质量要求](https://github.com/wisdom-km/open-immerse/blob/e9e00e47481d566188f73e5cbbd0c9a90463207d/pdf/high-precision/REQUIREMENTS.md) 和 [通读流规格](https://github.com/wisdom-km/open-immerse/blob/e9e00e47481d566188f73e5cbbd0c9a90463207d/pdf/PDF-MD-READOUT.md)。
原页裁图与识别 LaTeX 分别记录来源和验证状态；不能把 OCR 候选直接冒充原 PDF 的可信文字或原公式。
未核验公式保留原图和候选 LaTeX；多模态核验仍未通过则继续显示原图，禁止因“模型已回答”自动提升为可信公式。
PDF.js 预览与 Python 页面渲染允许不同像素尺寸，但必须共享页索引、旋转、页面框和显式坐标变换。

## 8. 存储、同步与凭据边界

桌面 SQLite 存文献、解析元数据、块、译文、批注、进度、对话、任务和待同步变更；大文件存文件系统。
云端后续用 PostgreSQL 存账号/实体/版本/变更/任务，用对象存储存原 PDF、图片和音频；两边独立建物理 schema。
数据库和文件写入用暂存资产 → 校验摘要 → 提交引用的流程；失败暂存交清理任务回收，不留下可见的半份文献。

| 数据 | 同步与保留建议 |
| --- | --- |
| 原 PDF、已接受结构化结果 | 仅论文启用同步后进入长期同步库；内容摘要与版本一起保存。 |
| 进度、批注、对话 | 同步到同账号；批注正文和锚点分开，锚点失效不删除正文。 |
| 解析临时页图、失败中间件 | 按 TTL 定期清理；不因任务结束误删已被文献引用的资产。 |
| 朗读音频与脚本 | 是否离线下载、跨端缓存待确认；元数据要能定位论文版本和来源块。 |
| 原录音 | 转写任务与最终笔记分离；长期保存/同步默认策略仍待确认。 |
| API key、Authorization、自定义含密钥 header | 不同步、不导出、不进入普通任务 JSON 与诊断日志。 |

临时远程解析上传与长期账号同步是两项授权：未开同步也可主动远程解析，但临时副本按约定清理。
同步关闭后的远端历史、删除传播与回收站周期待确认；“关闭同步”不能默认解释为立即删除所有设备文件。
同步首版建议采用服务端版本 + 变更游标 + 删除标记；不复制 SQLite 数据库文件，不直接比较设备时间判输赢。
批注冲突建议保留副本；对话以消息追加并维护顺序；阅读进度分设备记录再选最近活动，具体规则待用户确认。

桌面凭据仅在受控进程解密，使用 Electron [safeStorage](https://www.electronjs.org/docs/latest/api/safe-storage) 的平台加密能力保存密文；并非所有明文都直接存入系统钥匙串。
锁定版本后验证相应 API、加密可用性和升级行为；不可用时要求重新输入或仅会话持有，不静默明文落盘。
远程 worker 要用自身部署的凭据；后续手机云任务不能自动取得保存在桌面的 API key。
若未来需要官方代持用户密钥，应另设云凭据库、撤销和授权方案；本草案不将其纳入首版。

## 9. 手机派任务与在线桌面接单

后续手机先通过同账号应用 API 上传/选择论文、提交任务、订阅进度、取回结果，并从来源锚点继续阅读或收听。
云通道负责身份、任务记录和状态传递；实际执行可以是用户自建服务或未来托管 worker，不能只凭“有云 API”保证有算力。
官方收费云入口首版只保留 capability / provider 类型与禁用说明，不伪造可用套餐或任务服务。
已确认：桌面离线时，手机只要联网且配置了可用、具有预算的远程服务，就能独立完成解析与后续流程。
手机不必等待桌面上线，也不要求官方收费云先存在；云端电脑或用户自建服务可承担执行。
无可用执行服务、远端凭据未配置或预算不足时，任务进入 waiting-service / waiting-budget，明确显示原因和恢复条件。
手机本身离线时先保存任务意图，网络恢复后才提交远程执行；不把“桌面离线可运行”解释为远程推理无需网络。

在线桌面接单作为再后续能力：桌面主动建立出站连接，登记设备能力和允许的任务类型，按租约领取任务。
手机不直接访问桌面的 localhost，也不要求用户把 SQLite 或本地推理端口暴露公网。
设备休眠、离线或租约失效后，任务记录转为等待设备或可重新调度；不得重复执行同一已生效任务。
执行目标与费用策略使用用户设置；是否允许转到其他供应商及桌面电池执行另由配置约束，首版不实现远程桌面代理。

## 10. 语音接口、音频产物与引用锚点

```ts
interface AsrPort { transcribe(input: AudioInput): Promise<TranscriptArtifact> }
interface TtsPort { synthesize(input: SpeechScript): AsyncIterable<AudioChunk> }
interface RealtimeVoicePort { connect(input: VoiceSessionRequest): Promise<VoiceSession> }
```

ASR：音频资产 → 分段转写 → 用户确认或编辑 → Note；转写文本不是未经确认的原论文内容。
TTS：确定论文版本 + 译文/笔记 → 可检查的讲解脚本 → 音频；逐字朗读和总结讲解分别标注。
RealtimeVoice 后续独立设计双向音频、打断、转写事件和会话恢复，不能把 TTS 流当成实时对话已完成。
`ContentAnchor` 使用 02 文档的 documentHash、pageNumber、pageRevisionId、blockId 与 quote；范围引用可附 offsets，并通过文献映射得到 documentId。
`AudioSegment` 记录脚本版本、起止时间和 sourceAnchors；用户点击讲解段落能回到对应原文证据。
引用失效时显示旧版本和待重定位状态，禁止把讲解内容随意锚到另一篇论文或另一版本同序号的块。
语音 provider 复用凭据/网络端口；桌面与手机分别实现录音、权限、后台播放和音频焦点。

### 10.1 PDF 核心之后的独立写作能力

已确认首批写作为带引用的大纲、段落草稿以及 Markdown / LaTeX 导出；完整富编辑器、TeX 编译与协同编辑后置。
写作输入为用户选定的文献版本、笔记和意图；WritingProject / DraftSection / CitationLink 由 writing 域管理。
每条来源引用指向 ContentAnchor；无法验证的引用标为待核对，不能编造文献条目或把生成观点记为原文事实。
导出同时携带引用映射和所需素材清单；LaTeX 导出是否可编译在后续编译能力落地前不宣称已验证。
写作通过文献查询契约获取内容，与阅读 UI 和解析 worker 解耦；可与云端/手机接口阶段并行开发。

## 11. 云端扩展路线

最初需要上线时采用模块化 Node 应用 + 独立 Python worker；文献、任务、同步、语音是模块，不立刻拆微服务。
任务可先用数据库持久队列和租约；何时加入独立队列由并发、任务时长和故障恢复证据决定。
GPU worker 可按引擎和硬件单独部署；应用服务不因加载新模型而重启，模型服务不直接访问用户业务表。
后续按实际瓶颈拆任务调度、资产处理或同步服务，再加入配额、计费和团队权限；官方收费业务需另行需求确认。
日志关联 requestId/jobId/parseRunId，保留阶段耗时、失败码、重试和 provider 用量；不记录全文与密钥作为默认诊断。
自建服务与托管服务共享协议，部署地址和凭据绑定执行环境；避免把商业厂商地址固化到领域层。

每阶段保留协议样例、代表性论文、数据备份和可重放结果；桌面 GUI 验收与单元/接口测试分别记录。

解析与模型许可、硬件占用、质量阈值、供应方能力需用锁定版本实测；本草案没有证明它们已达标。

## 13. 首版自建解析服务与后续账号 API 的区别

首版远程解析必须有可用的服务端入口，不能等后续 `cloud-api` 上线才补。建议在 `services/parser-worker/api/` 提供薄的 Python/FastAPI HTTP 入口，调用同目录引擎与运行时；通过独立服务访问令牌保护，提供 capability、提交、状态、事件、取消和产物获取。该入口管理解析运行及临时产物，不管理用户文献库或发布当前采用版本。

同机和远程均通过 ParseEngine/JobExecutor 端口进入；第三方 OCR/模型服务由 provider adapter 映射，不能假定它们实现本项目的 URL。自部署交付包含运行配置示例、按引擎选择的运行时/容器和检活/协议测试；模型权重与 GPU 依赖在服务端按需部署。无需完整账号平台，就应跑通桌面 → 自建远程解析 → 规范化产物 → 桌面文献库的首版闭环。

未来 `services/cloud-api/` 才承担账号、文献权限、同步、设备、统一应用任务和配额；复用 TS 用例，经内部适配器调用同一解析服务。首版自建服务访问令牌不是未来多用户账号系统，也不能拿它作为所有用户共同的永久凭据。

账号接口先冻结身份语义：userId、deviceId、sessionId，以及会话刷新/撤销；文献、资产、任务和同步变更按所属用户检查访问权。可预留 `GET /v1/me`、设备注册、会话刷新和撤销端口，由后续身份适配器实现。桌面本地使用本机命名空间，未启用账号时仍可阅读和管理自己的资料；账号登录后建立明确绑定，不按本机绝对路径识别用户。

每个领域模块以公开 facade/commands/events 与外部交互；跨域不能 import 对方的私有状态、SQL 或 React 组件。先用编译时公开边界和类型化事件实现扩展性，不为尚无需求的第三方插件市场建设动态加载框架。新增朗读模块应只新增语音用例、provider 和 UI 入口，并消费 ContentAnchor；不要求重写阅读器或解析引擎。

FastAPI 可利用其 [OpenAPI 与 JSON Schema 支持](https://fastapi.tiangolo.com/features/) 暴露协议；框架自身的版本和生成器在 P0 锁定。推理服务可能使用不同 Python 环境，不能因统一 HTTP 入口而强制它们共享一个依赖环境。
