# 双引擎与质量评估草案

状态：设计草案；截至 2026-10-30 已核对官方文档与部分实现，未经实际模型推理验证。

本文只定义拟采用的产品协议与路由规则，不代表上游原生 API，也不表示性能或成本已获验收。

唯一实施目标为新仓库 [open-immerse-v2](https://github.com/wisdom-km/open-immerse-v2)。旧仓库只作规格、算法与迁移参考，保持不变；新产品不包含浏览器扩展和网页翻译入口。

## 1. 已固定的要求与后续定标项

- 输入统一使用 PyMuPDF 做文字层检测、文本提取及模型输入页面渲染。
- 分支 A 为主力：PP-DocLayout、PP-FormulaNet、自写阅读顺序、PDF 文字层优先、PaddleOCR 兜底。
- 分支 B 使用 MiniCPM-OCR 1.0 官方完整解析流水线，承担对比与兜底。
- 两条分支统一产出可追溯的块结构，以及结构化 Markdown、LaTeX 派生输出。
- Jev 负责区域识别结果评分；通用多模态只处理低分区域。
- 对低分或有明确不确定证据的公式，必须具备调用多模态核验的能力；设置中提供自动补救开关。
- 用户可选择受限预算或不设金额上限；高额度自有 API 可选择后者，但技术超时、并发和重试仍有限。
- 未核验公式先显示原始 PDF 区域图，LaTeX 作为候选保留供复核；核验仍不过时继续显示原图。
- 翻译仅作用于自然语言，LaTeX 和公式占位符必须经过确定性完整性校验。
- 桌面最低目标包含 8 GB 内存、核显或 M1 等设备；该目标不等于承诺这些设备可同时本地运行全部模型。
- 首版使用用户自己的 API 或自建推理服务；重推理默认走用户配置的远程服务。
- 模型与推理运行时按需选装，不应成为桌面安装、打开原文、管理书库的必要条件。
- 为后续官方云入口、账号及手机任务接入保留服务接口，首版不因此建设完整云平台。

自动补救方式已确认为用户可配置开关，预算已确认为受限/不设金额上限两种模式，无需再次征求这一策略选择。
Jev 分类阈值、受限预算的具体金额、分支切换阈值以及有限重试次数属于后续样本测试与产品配置定标项。
运行时按用户已保存的开关、服务和预算设置执行；关闭自动补救时保留手动核验入口。

## 2. 实际上游能力与命名边界

Paddle 官方公开了 PP-DocLayout-L、PP-DocLayout_plus-L，以及 PP-FormulaNet-L、PP-FormulaNet_plus-L 等模型与推理权重。
最终采用的具体型号、依赖版本和权重摘要应进入模型清单，不能只记录系列名称。
PP-DocLayoutV3 已包含布局和阅读顺序能力；分支 A 仍按本项目要求使用自写阅读顺序算法。
模型提供的顺序可以保留为候选或对照证据，不应悄悄替换项目所声明的排序算法。

MiniCPM-OCR 1.0 官方 SDK 实际包含以下步骤：

```text
页面图 → PP-DocLayoutV3 → 区域裁剪 → MiniCPM-OCR 1.0 识别 → 按顺序组装
```

因此分支 B 是端到端使用的完整流水线，不是单个识别模型独自完成全部布局与顺序任务。
专用 MiniCPM OCR 在分支 B 中承担常规解析；“仅低分区域使用多模态”限制的是额外的通用多模态补救步骤。
当 A、B 均采用 PP-DocLayoutV3 时，两者的布局判断存在共同依赖，不能把它们宣传为完全独立的识别专家。

## 3. 公共预处理与桌面渲染的职责

```text
原始 PDF + SHA-256
  → PyMuPDF 预处理产物
  → A / B 独立解析运行
  → 统一块结构及质量检查
  → Jev 评分与可选低分补救
  → 翻译及完整性检查
  → 阅读视图与导出
```

PyMuPDF 负责为模型生成可复现的页面图，并保留每页文字层、页面尺寸、裁切框、旋转与渲染参数。
约 300 DPI 是候选配置，最终应根据模型输入限制、清晰度、内存和网络传输量选择，不能作为不可变常量。
PDF.js 用于桌面左栏原文浏览、缩放、选区及定位；它不应另行成为一套未经映射的模型坐标来源。
页面图像素坐标、PDF 用户空间坐标和现有块协议归一化坐标必须通过显式变换矩阵关联。
坐标变换还应记录页面旋转、CropBox、缩放和裁剪偏移，避免仅按宽高比例处理旋转页面。
原始模型输出和映射后的规范坐标均应保留，便于定位坐标错误。

文字层检测按页进行，文字层是否可信按区域判断：可提取字符并不自动等于阅读顺序或文本完整性可靠。
空白文本、异常字符比例、图文覆盖、区域错配和可疑缺字应触发区域问题标记。
扫描页或文字层不可靠区域才进入 OCR；混合 PDF 不必整篇强制 OCR。

## 4. 分支 A：百度模块化主力

1. PP-DocLayout 输出候选布局区域，保留类别、边界框与模型检测分数。
2. 用公共预处理文字层与区域几何关系匹配正文，排除图、表、公式内部字符进入正文。
3. 对无可靠文字层的文本区域调用 PaddleOCR，并标记来源为 OCR 候选。
4. 对独立公式和行内公式区域裁剪，使用 PP-FormulaNet 生成 LaTeX 候选。
5. 表格模块输出结构候选；是否首版处理合并单元格、跨页表格仍需在范围中明确。
6. 自写排序处理单栏、双栏、跨栏标题、跨栏图表、脚注和参考文献。
7. 将结果映射到统一块协议，再进行结构完整性检查与 Jev 评分。

排序算法应版本化，并保留栏分组、跨栏判定和前后关系，方便人工纠错与回归比较。
多栏区域不宜只按全页 y、x 简单排序；跨栏元素应成为分区边界或顺序约束。
正文中的断词、跨行与跨页合并应保留原始 span 和合并理由，不覆盖文字层原始证据。

## 5. 分支 B：MiniCPM 完整流水线

优先接 SDK 的块级中间结果，而非只接最终 Markdown。
官方布局记录含 block_id、label、bbox、regions、order、score、裁剪文件名及图像尺寸等字段。
这些字段足以支持规范化适配，但官方顺序编号不是本项目长期稳定的业务 ID。
应使用适配器连接公共页面图与 SDK 布局/识别阶段；如果具体版本必须重渲染 PDF，应验证两套页面图的坐标映射。
SDK 与识别服务可在不同机器运行；桌面端不应假定它们共享文件路径。
表格由官方流水线将 OTSL 转 HTML，公式保留 LaTeX；应保留其原始输出，不能强制压平成纯文本。
若所接远程服务只返回 Markdown，缺少 bbox 等证据，应声明能力降级；不满足精确定位要求时不能冒充完整引擎。

## 6. 拟议 ParseEngine 协议

以下是本项目拟议接口，不是 Paddle、MiniCPM 或现有仓库已经存在的 API。

```ts
type EngineId = 'paddle-modular' | 'minicpm-pipeline';
type ArtifactRef = { id: string; sha256: string; mediaType: string };
type ParseRequest = {
  documentId: string;
  documentRevision: string;
  preprocessingId: string;
  pages?: number[]; // 规范协议统一使用 1 起始页码
  regions?: { page: number; regionId: string }[];
  engineConfigId: string;
  idempotencyKey: string;
};
type EngineCapabilities = {
  engineId: EngineId;
  regionParsing: boolean;
  layoutBoxes: boolean;
  latex: boolean;
  structuredTables: boolean;
  cancellation: 'immediate' | 'cooperative' | 'unsupported';
};
interface ParseEngine {
  capabilities(): Promise<EngineCapabilities>;
  submit(request: ParseRequest): Promise<{ parseRunId: string }>;
  inspect(parseRunId: string): Promise<ParseRunSnapshot>;
  events(parseRunId: string, afterEventId?: string): AsyncIterable<ParseEvent>;
  cancel(parseRunId: string): Promise<{ accepted: boolean }>;
  artifacts(parseRunId: string): Promise<ArtifactRef[]>;
}
```

ParseRunSnapshot、ParseEvent 的完整 schema 由统一协议包定义；事件至少覆盖阶段变化、页完成、区域失败和取消完成。
submit 返回任务标识，不要求客户端在一个 HTTP 请求中等待整篇 PDF 完成。
无区域解析能力的适配器应明确拒绝区域请求，或返回需整页运行的计划，不能隐式扩大收费范围。
配置引用对应受保护的服务配置，任务请求和日志中不包含明文 API Key。
跨进程或远程调用用版本化 HTTP API；进度可用 SSE，交互式双向能力另行选择 WebSocket。

## 7. 上游实际输出到统一模型的映射

| 上游字段或行为 | 本项目规范化处理 |
| --- | --- |
| Paddle boxes[].coordinate | 记录原像素框，再映射到规范坐标；验证页面尺寸与旋转 |
| Paddle cls_id、label | 映射为规范块类型，同时保留原始类别和映射版本 |
| Paddle score | 保存为 layoutDetectionScore，不能当文本正确率或 Jev 分数 |
| PP-FormulaNet rec_formula | 保存 LaTeX 候选；继承裁剪区域的坐标、来源与关联 ID |
| MiniCPM block_id、order | 保存运行内标识与顺序；另建稳定业务块标识 |
| MiniCPM regions | 保存多区域证据，避免合并后只剩一个过大的外接框 |
| MiniCPM HTML 表格 | 保存结构与原始内容；Markdown 导出时说明复杂结构降级 |
| 任一引擎最终 Markdown | 作为派生物，不能替代 bbox、来源、公式关联和修订记录 |

建议每个候选记录 parseRunId、模型/权重版本、regionId、sourceKind、rawArtifactRef、产生时间和质量状态。
原始 PDF 页面裁剪与模型生成的 LaTeX/表格结构分开存储；未经核验的识别候选不覆盖可信原文对象。
该分离尤其用于迁移现有 high-precision 中“视觉对象不得冒充可信原文文本”的约束。
公式保存 originalCropRef、latexCandidates、verificationStatus 与核验记录，显示状态默认指向原图。
通过核验的 LaTeX 可以提供可切换的结构化呈现；原图仍保留为对照和失败兜底，不能被候选替换或删除。
Markdown 和 LaTeX 输出应能定位到具体块、候选和原始页面证据，而不是创建不可追溯的独立文本。

## 8. 引擎切换与独立运行

切换引擎只影响新运行；既有结果、译文和人工修订保留所属源文档版本、pageRevisionId 与 parseRunId。
同一预处理产物分别创建 A、B 两次运行，并记录各自配置、耗时和失败，不混用缓存键。
缓存键至少包含 PDF 摘要、预处理参数、区域摘要、引擎版本、模型版本及关键配置。
比较结果先进行区域匹配，允许一对多和多对一，不能假定两条分支输出相同数量的块。
候选选择形成新的 AcceptedPageRevision，并记录被选候选与原因，不覆盖两条原始运行；类型与字段以 02 文档的数据协议为准。
只有原文身份、内容及公式结构通过兼容性校验后，才考虑复用旧译文；仅有相同顺序编号不够。
用户手工确认过的块应有保护状态，重新运行不能无提示替换人工修订。

## 9. Jev 评分协议与边界

Jev 输入是原区域图、候选内容与其渲染图，并需要正确的 text、formula 或 table 类别。
官方服务可代为渲染；如果自行渲染，应记录渲染器及配置，否则评分可比性可能改变。
只有 verdict 为 scored 的返回值才是有效模型分数。
render_error 等情况返回的 0、encode_error/forward_error 等情况返回的 -1 都是错误占位，不能当作低置信度。
规范 evaluation.status 与 02 文档统一为 scored / error / unavailable / not-run；只有 scored 可携带有效 rawScore。
厂商 verdict 原样保留在 providerVerdict，invalid_candidate、render_failed、service_failed 等适配器原因记为 detailCode；例如渲染/编码/推理失败映射 error，未配置服务映射 unavailable，未运行映射 not-run，不能混为模型低分。
0–1 分数用于候选排序和筛选，不直接等于字符准确率、逐字符置信度或已校准的正确概率。
官方 API 的默认 threshold 为 0.5 不代表本产品适用；正文、公式、表格应分别用实际样本校准。
Jev 不直接验收整页是否漏块、全篇阅读顺序是否正确或翻译是否忠实；这些必须保留独立校验。

## 10. 低分区域补救与预算

```text
有效 Jev 低分 → 检查自动补救设置与预算 → 生成区域补救计划
  → 可选分支 B 区域候选 → 重新评分
  → 仍低分时调用通用多模态 → 重新评分与结构检查
  → 保留最佳有效候选，或转人工复核

公式存在明确不确定证据 → 检查核验设置与预算 → 多模态核验
  → 重新评分与结构检查 → 通过后保留核验记录；仍不过则继续显示原图
```

上图是推荐的执行路由；是否自动运行由用户设置决定，候选分支优先级与数值阈值由基准测试定标。
“仅对低分区域使用通用多模态”是固定范围约束；有明确不确定证据的公式进入同一质量问题区域集合，不扩展成整页或全文多模态处理。
公式不确定证据可以来自公式结构校验失败、候选间实质差异、文字层与识别结果冲突或用户标记；记录具体原因后才进入核验计划。
未经评级只表示尚无评分，服务错误只表示评分失败；二者不能单独作为内容低分或公式不确定的证据。
未核验、低分、明确不确定和核验失败公式均先显示原图，LaTeX 候选及历次结果保留供复核；自动核验按已保存开关执行。
分支 B 不支持区域识别时，应先显示实际所需的整页范围和估计成本，再按已确认策略处理。
Jev 服务失败走服务重试或等待路径；不能因为服务失败直接判定原内容错误并调用多模态。
多模态只收到目标区域与必要上下文，任务是补充转录或结构识别，不同时承担整页布局及翻译。
候选返回后重新执行 LaTeX 语法/占位符、区域结构检查与 Jev 评估，不能因“来自更大模型”自动通过。
公式核验需要对照原始公式区域与候选内容，保留核验结论和修正候选；渲染成功或多模态声称正确均不能独立作为通过标准。
设置项建议包含 autoRepairEnabled、budgetMode（limited/uncapped）、受限金额及币种，并明确预算作用于单文档还是当前处理批次。
受限模式在额度达到后停止提交新的收费补救请求，保留原图与候选，提示“额度已达上限，请复核或调整额度”。
不设金额上限模式仍记录调用及费用，不表示无限循环；每区域次数、每文档次数、并发、输入图尺寸、token 和超时均设有限技术上限。
自动补救入口只接受有效低分或已记录具体不确定证据的区域；设置为不设金额上限不会扩大通用多模态的处理范围。
费用估算依赖服务单价与实际 usage；未知单价或缺少 usage 应标记未知，不能记为零费用。
软件内用户设定的补救预算与供应商账户真实剩余额度分别显示；只有供应商确实提供余额/配额 API 时才读取实时额度，不能根据本 App 的历史用量推断整个账户还剩多少钱。
受限预算模式下无法估算所需额度时，应等待用户补齐价格配置或调整预算模式，避免悄悄突破已选限额。
预算预留与实际结算应原子化，取消后的在途请求也可能产生费用，必须在任务状态中反映。
全部候选仍低分或检查失败时保留原图、候选和原因，进入待复核状态，不编造完整输出。

## 11. 部署模式与桌面资源控制

默认模式：桌面负责原文浏览、任务管理及轻量预处理，Paddle、MiniCPM、Jev 重推理由用户配置的服务承担。
预处理单独进程运行，页面图按需生成并限制缓存与并发，避免 8 GB 设备一次加载整篇高 DPI 页面。
选装模式：用户按能力检测结果下载特定运行时与模型；CPU、CUDA、Metal 等运行路径分别验证。
Paddle 与 MiniCPM/Jev 可使用隔离环境或独立服务，避免将互相牵制的 Python、Torch、Paddle 版本塞入同一环境。
官方 MiniCPM vLLM 教程验证 Linux x86_64 与 RTX 5090 32 GB；这不是最低硬件声明。
官方另有 llama.cpp CPU 路径、Apple Silicon Metal 路径；仍须在目标设备测量速度、峰值内存与稳定性。
远程服务按 ArtifactRef 交换产物，通过鉴权上传或短期授权下载，不依赖桌面磁盘绝对路径。
未来官方云只需实现同一执行与产物接口；用户配置与官方服务通过 providerId 区分。
手机可提交同类任务、订阅进度和读取产物；账号、设备权限、文件同步与费用归属在服务层扩展。
未来手机通过远程服务独立完成解析、评分和翻译，不要求桌面在线或本机具备高配置 GPU；公共预处理也可由远程服务执行。
无可用服务、服务暂不可达或预算不足时，任务进入 waiting 状态并记录原因，继续展示已有产物或原图；不会强制回退到手机/低配置桌面运行重模型。

## 12. 基准测试与分阶段验收

先固定一组可合法使用的代表论文，覆盖文字层 PDF、扫描 PDF、双栏、跨栏、密集行内公式、复杂表格及旋转页面。
标注页面/区域来源、完整性、阅读顺序、正文内容、公式与表格真值，并将阈值校准集和独立测试集分离。
分别运行 A、B，不共享识别候选；比较同样的输入、版本和资源条件。
质量指标至少包括漏块/重复块、bbox 匹配、阅读顺序错误、正文 CER、公式结构准确率及表格结构指标。
Jev 另测有效评分覆盖率、服务/渲染失败率、不同阈值的自动接受率与接受结果准确率。
翻译验收另测公式占位符顺序、LaTeX 哈希一致性、引用编号、块身份及译文与原文对应关系。
公式场景还需验证未核验默认显示原图、LaTeX 候选可复核、低分/明确不确定可调用多模态核验、仍不通过继续显示原图，以及评分服务失败不会误触发收费补救。
工程指标记录冷启动、首个可读页时间、总耗时、峰值内存/显存、上传量、调用量、费用与取消后的资源释放。
本地和远程结果分开报告；模拟 API、自动单测、真实推理与人工视觉验收分别标注，不混为通过。
第一阶段验收公共预处理及 A 的可追溯解析；第二阶段接 B 和统一比较；第三阶段接 Jev 与经确认的补救策略。
上述真实测试完成前，不承诺普通核显、M1 或 8 GB 设备的全模型本地性能。
