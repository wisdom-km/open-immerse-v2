### 8.2 桌面存储布局

```text
<userData>/
├─ db/oi.sqlite                 # WAL；单写者（main 或 utility 进程）
├─ library/<sha256>/source.pdf  # 原 PDF，只读
├─ assets/<sha256-prefix>/<assetId>   # 裁图、页面图、音频；内容寻址
├─ staging/                     # 暂存；提交成功后移动，失败由清理任务回收
├─ logs/YYYY-MM-DD.jsonl        # 结构化日志，保留天数与总量上限见 diagnostics
└─ secrets.bin                  # safeStorage 密文；不入 SQLite、不随导出
```

- 表按切片加前缀（`lib_`、`doc_`、`job_`、`fsrc_`、`tr_`、`md_`、`note_`、`qa_`、`voice_`、`set_`、`bud_`、`diag_`、`ing_`；`ing_` 只存用户选的路线，不存流水线进度，§7.12；`wr_` 为 writing 预留），只有拥有该前缀的切片的 adapters 可以读写。跨切片查询走对方的用例，不跨前缀 JOIN。
- 用户的 `.md` 文件与笔记库**不复制**进 `<userData>`：`md_` 表只存最近打开列表与已登记的外部图片资产（绝对路径只在本机，§4.5.5）；`assets/` 不保存笔记库图片的副本，`oi-asset://` 按登记的路径实时读取并重新做库内检查。
- 迁移文件放在各切片 `migrations/`，运行器按（切片, 版本号）排序执行并记录在 `schema_migrations`；**两个切片的迁移永远不会改同一个文件**。
- 写入顺序：资产写暂存 → 校验摘要 → 事务内写引用 → 提交。失败不留半份文献。
- 采用版本切换使用乐观锁（比较旧 `revisionId`）；过期任务结果不能覆盖新版本。
- **数据目录迁移（已采纳，ADR 0001，Wisdom 2026-11-04）**：`<userData>` 改为可迁移的数据根 `dataRoot`。固定位置保留一个小指针文件记录当前 `dataRoot`（文件名与位置由 Forge 定）。迁移顺序：检查（目标为空、可写、可用空间 ≥ 1.2 × 数据大小、不在笔记库或系统目录、不在当前根内）→ 停止写入与任务 → 复制 → 逐个校验 → 原子更新指针（commit 点，之前可取消）→ 重启 → 询问是否删除旧根。失败或取消：指针不变、清理目标、旧根未改动。`secrets.bin`（safeStorage）同机迁移是否可直接复制**还没核实**，否则迁移后重新加密或提示重填 Key。`staging/`、`logs/` 迁移或清空由 Forge 定。
