### 7.12 处理路线：独立积木与声明式组合（Wisdom 2026-10-30 22:41、22:44、22:45）

22:45 取代「把 A / B / C 写成三套固定路线」。处理一篇文献用到的能力分成四类积木，每类一个端口，本地、第三方 API、以后的自有托管服务都是该端口的实现。增加一种实现不改 core，也不改其他积木。一条路线是这些积木的一份配置；换路线只改配置。积木之间只通过统一文档模型与对方的 seam 交换数据，禁止在 core 或某个积木里写死另一个积木（RULES N-20）。界面只定行为，布局与文案待 Loom。

| 类 | 端口 | 现在的实现 | 开关 |
| --- | --- | --- | --- |
| 版面 | `parsing` 的 `LayoutEngine`（独立的 `layout` 作业，与引擎 A 的识别阶段不是同一次作业，§7.2、§10.2）。部署只读 `RouteConfig.layout`，不读引擎 A 的「本地 / API」（D-D，Wisdom 2026-10-31） | PP-DocLayout（标准档 V3，高质量档 plus-L 仍按 Q10，不在这里重开）。本地与自建远程 worker 是同一份代码、同一协议（HTTP + SSE，§10）。查阅范围内没有已确认的 PP-DocLayout 托管版面 API：百度 AI Studio 的 PaddleOCR API 能否返回版面区域仍是「未核实」（§7.0），核实通过之前不把它写成版面服务商，也不登记虚构的托管服务商，`deployment: 'api'` 不发请求。以后换别的版面模型，只加一个 `LayoutEngine` 实现 | 可以关掉。关着时不切块。整页只走多模态，再用文字层校正（本节「版面关掉时的整页坐标」，AC-95）。引擎 A 的识别（`parse`）、引擎 B、云 OCR 请求都为 0，不发整页（D-E，Wisdom 2026-10-31 11:14）。引擎 A 只消费版面裁片。引擎 B 的 SDK 内部会跑 PP-DocLayoutV3，跑它等于悄悄把版面加回来。识别列表含这三项之一且版面关着时，`route-config` 校验失败，原因码 `sources_require_layout`，不静默跳过。四个预设不改。已知代价：没有 OCR 兜底，只剩多模态，再按裁图、占位框降级。阅读顺序在坐标对得上时仍由 `reading_order` 校验（§7.10） |
| 识别来源 | 各来源自己的端口（`parse` 作业、`OcrProvider`、`MultimodalProvider`、`formula-source`） | 多模态、云 OCR、引擎 A 的识别阶段（公式、OCR 兜底、表格）、引擎 B、arXiv 源码。arXiv 只在文献有编号时运行，四个预设都带上它 | 版面开着时，每个来源单独列入或移出路线。版面关掉时只能留多模态与 arXiv；引擎 A、引擎 B、云 OCR 列入则校验失败（上一行）。可信文字层页上的正文仍用文字层，不交给这些来源 |
| 结果判定 | `quality` 的评估端口，以及 `formula` 的 `program-check`、`source-check-standing` | Jev、程序核对（§7.5）、源码核对（§7.5 第 4 步） | 评分开关优先于判定列表里的 Jev（§7.4，Wisdom 2026-10-30 23:55）：开关关着时所有路线都跳过 Jev，标「未评分」，路线配置不改写；路线含 Jev 时界面提示「当前路线包含评分，但评分已关闭」（文案待 Loom）。开关开着且列表含 Jev 时，所有来源一视同仁地送评。开关开着且列表不含 Jev 时不送评，公式走 §7.5 第 4、5 步：第 5 步通过标「格式已核对」，不算已核验（Wisdom 2026-10-31 01:14）。程序核对在标已核验之前要过，在标「格式已核对」之前也要过：含 Jev 且开关开着时是第 1、2 步的四项，没有 Jev 分数时是第 4、5 步。源码核对在记录为 `not-run/disabled` 且 arXiv 候选通过覆盖率与逐公式核对时出现；算不算已核验仍待定，当前不算。仅多模态的位置用校正后的框，不用版面公式区域 |
| 兜底 | `document` 的 `display-fallback` | 原页裁图，再是占位框「图见原文第 N 页（点击查看）」，点击跳到左侧原文该页（§7.5 第 6 步） | 链本身不去掉。替换是换这个端口的实现，不是在别的积木里另写一套降级 |

**每个区块带坐标。** 版面开着时，PP-DocLayout 先切出正文、行内公式、行间公式、图、表并给出阅读顺序，再把每个区块裁成小图交给识别来源，也交给翻译（翻译仍按 §8.1.1 的块，不整页送）。识别不准或程序核对没过，就退到这个区块的裁图，再退到占位框。行内公式、行间公式、图、表都走这条链。

**预设。** 定义与「这份配置对应哪个预设」的判断，只在 `ingest/domain/route-presets.ts`。内置四个，用户也可以在这四类的取值范围内改成自定义组合。它们是配置，不是写死的 A / B / C 路线。

| id | 名称 | 版面 | 识别 | 判定 | 说明 |
| --- | --- | --- | --- | --- | --- |
| `multimodal-layout` | 多模态+版面 | PP-DocLayout，部署不默认本机（本机只留 stub；Wisdom 2026-11-02；只属于版面，不是引擎 A 的开关） | 多模态（按区块） | 程序核对；不含 Jev | 22:41 里「A 路线」要采用的组合。新安装与恢复默认的过渡预设是这一行（W-4，Wisdom 2026-10-31）。正式全局默认仍等 M0。不论开关，第 5 步通过标「格式已核对」，第 4 步通过标「源码核对」，都不标已核验 |
| `multimodal-only` | 仅多模态 | 关 | 多模态（整页，坐标见下） | 程序核对；不含 Jev | 版面关掉。位置核对用校正后的框，不用版面公式区域。显示标签与上一行相同，不标已核验 |
| `ocr-layout` | OCR+版面 | PP-DocLayout，部署不默认本机（本机只留 stub） | 引擎 A 的识别阶段；引擎 B 作对比 | 程序核对；不含 Jev | 识别列表含引擎 B。引擎 B 请求不为 0 只在这一行和下一行。显示标签与「多模态+版面」相同，不标已核验 |
| `ocr-layout-jev` | OCR+版面+Jev | 同上 | 同上 | 判定列表含 Jev；没有分数时仍用程序核对与源码核对 | 现有方案的一种预设。是否送评还看评分开关（§7.4） |

云 OCR 不在任何一个预设里默认打开（它是额外的付费来源，用户配好后加入识别列表）。四个预设的识别列表不改：`multimodal-only` 本来就不含引擎 A、引擎 B、云 OCR，校验通过。版面关掉的自定义组合若把这三项写入识别列表，`route-config` 校验失败，原因码 `sources_require_layout`，不写入 `ing_route`，也不改成静默跳过（D-E，Wisdom 2026-10-31 11:14）。已存路线读出来仍是这种组合时，`open-document` 不提交作业，返回同一原因。四个预设都含 arXiv 源码。arXiv 不是按版面裁片识别的来源，版面关掉时仍可留在列表里。**正式全局默认仍待定**（Wisdom 2026-10-30 23:55；2026-10-31 只定过渡默认，W-4）：等 M0 在同一批论文上对比这四个预设的质量、面壁 API 单篇耗时、客户端内存（不含本地模型）之后，由 Wisdom 决定写进 `route-presets.ts` 的正式 `defaultPresetId`。在那之前，新安装与恢复默认的过渡预设 id 是 `multimodal-layout`，不是空，也不要求用户先选一条。`open-document` 按这份已选预设提交版面、识别或评分作业。升级保留用户已选的路线，不把已有选择改写成过渡默认。`ing_route` 缺失、读不出一份路线时不提交作业。选预设只改 `ing_route`，不改评分开关。拨评分开关不改路线，也不把路线记成自定义（§7.4，PRD AC-97）。来源优先级的默认顺序仍是现行提议，W-4 里该项未决，本节不改顺序。

**`RouteConfig`（拟议，`contracts/src/route.ts`）。** 换预设不迁移文档模型。`ing_route` 只有一行，列是 `schema_version` 与配置 JSON。

```ts
type RouteConfig = Readonly<{
  schemaVersion: 1;
  presetId: string | null;              // 对上某个预设时填 id；自定义时为 null。新安装写入过渡默认 multimodal-layout，不是 null
  layout: Readonly<{ enabled: boolean; deployment: 'local' | 'remote' | 'api' }> | null;
  recognition: readonly string[];        // 来源 id：multimodal、cloud-ocr、engine-a、engine-b、arxiv
  judgment: readonly ('jev' | 'program-check' | 'source-check')[];
  fallback: 'crop-then-placeholder';
}>;
```

`ParseRun` 增加只读快照：`routePresetId` 与 `routeConfigDigest`（上面这份配置的规范化哈希，不含密钥）。事后能回答这篇文献当时走的哪条路线。文档模型的 `schemaVersion` 不随路线变（§8.4）。

**版面关掉时的整页坐标（Wisdom 2026-10-30 23:55，仅多模态）。** 多模态返回每个区块的大致坐标，程序再用 PDF 文字层比对校正。返回先规范化成下面的形状，再进入文档模型；具体服务商的 JSON 只在它的适配器里出现。

```ts
type WholePageRecognition = Readonly<{
  page: number;
  blocks: readonly WholePageBlock[];
}>;
type WholePageBlock = Readonly<{
  blockId: string;
  kind: 'paragraph' | 'heading' | 'formula_inline' | 'formula_display' | 'figure' | 'table' | 'caption' | 'other';
  text: string | null;
  latex: string | null;
  bbox: Readonly<{ x: number; y: number; width: number; height: number }> | null; // 0–1，左上原点，与 CoordinateFrame 同一帧；这是大致坐标。服务商没给框时为 null，进入精确区域的次数为 0（AC-95 ①）。本类型没有编号字段：仅多模态按「区域没有编号」处理，候选自带编号则编号核对不过；是否改这一条见 docs/backlog.md §8 R-B，标为「M0 实测后决定」，选定前不加字段
}>;
```

校正在 `document/domain/bbox-align.ts`：`bbox` 为 `null` 的区块不进入精确区域，文字仍保留，只做页级显示。有文字层且 `bbox` 不是 `null` 时，把区块里的文字与该页文字层字形比对，对得上的把框收到字形的外接框；这个校正后的框才是仅多模态路线上程序核对与 arXiv 对齐所用的位置（§7.5 第 5 步、§7.6，Wisdom 2026-10-31 00:46），不读校正前的大致坐标，也不读版面模型。对不上的区块只做页级显示（挂在这一页上，不当成有精确区域的块），位置核对不过；页级显示也做不到时，退到整页裁图，再退到占位框「图见原文第 N 页（点击查看）」。没有文字层时无法校正，这些区块都按对不上处理。对得上的区块之后仍走 §7.5 的降级链（区块裁图，再占位框）。点击页级显示或整页裁图时，左侧原文跳到第 N 页，不声称能定位到一个区域（PRD AC-95）。

**部署（D-D，Wisdom 2026-10-31）。** 版面的「本地 / API」和引擎 A 识别阶段的「本地 / API」是两个设置。版面只读 `RouteConfig.layout`。引擎 A 的设置只覆盖识别阶段的 `parse` 作业，不改 `layout`。界面可以提供一键路线预设，选中预设只写入这份配置，不把两个旋钮合成一个。每个积木仍可单独选本地、第三方 API 或自建远程。版面的远程在托管 API 核实之前只有自建远程 worker；`deployment: 'api'` 在核实之前不发请求。本机 PP-DocLayout 是第二路线（Wisdom 2026-11-02）：M0/M1 只留 `LayoutEngine` 端口、契约和 stub，不实现、不下载模型，不测冷启动、单页耗时、峰值内存或是否 OOM。这些本地项标为推迟，不删除。M0 要测的是面壁 API 的单篇耗时、单篇费用、失败率与重试，以及客户端内存（不含本地模型）；Key 不在时标「未核实」，不预填数字（PRD §8）。标准档仍是 PP-DocLayoutV3。PP-DocLayout_plus-L 仍按 Q10、QM-13，不在本机 CPU 上作为 M0 测量。

**代价。** 版面开着且按区块识别时，一页的外部调用从「一页一次」变成「一个区块一次」，常见是几次到十几次（按该页区块数，不是固定次数）。每一次都经预算闸门与外发同意（§7.8、§7.0 第 6 条）。版面切错会让后面的识别和翻译跟着错：`reading_order` 负责校验和兜底（§7.10）；校验不过的区域按兜底链退到该区块的裁图，再退到占位框。关掉版面时没有 OCR 兜底：引擎 A 的识别、引擎 B、云 OCR 都不运行。整页只走多模态，再按裁图、占位框降级（D-E，Wisdom 2026-10-31 11:14）。

**已处理的文献与按篇切换（待 Wisdom 确认）。** 规格先按最保守的写：切换路线不改写已有采用版本与译文；之后新解析的页，以及用户明确「按新路线重跑」的文献，才用新路线。是否自动重跑、能否按篇选择路线，见 [backlog](./docs/backlog.md) §8 W-2、W-3，标为「M0 后决定」，不在这次写成已决定。

**统一接口与账号（22:44）。** 本地 worker、第三方 API、以后的自有托管服务实现同一个能力端口。鉴权见 §7.9.5：API Key 与账号 token 都走 `ProviderAuthorizer`。订阅、计费、账号系统、托管服务端不进 v2，只预留 `AccountSession`。
