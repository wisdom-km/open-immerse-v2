#### 6.1.5 预算闸门（AC-63）

来自架构评审 P0-3（Wisdom 2026-10-30 19:57 批准；ARCHITECTURE §7.8）。core 测试 + 契约测试，用假服务，不花钱。

| 编号 | 标准 | 对应 |
| --- | --- | --- |
| AC-63 | 单价未知时的次数类上限：① 受限预算、Jev 与引擎 B 单价都未填，Jev 科目设请求数上限 N、引擎 B 科目设页数上限 M：对面壁 Jev 的上游请求数 ≤ N（含拆批与重试），文档解析的页数 ≤ M，超出部分的请求数为 0；超出的 Jev 项记 `unavailable/budget`、标「待评分」，补救请求为 0；超出的页引擎 B 产出 0 个候选；② 同样条件但该科目没有设次数类上限：对该科目的请求为 0（`budget_cap_unset`），界面提示去填单价或上限；③ 单价未知的费用在界面显示「未知」，0 次显示为 0，也 0 次被加进金额合计；④ 经 worker 的作业：worker 收到的额度信封为 K 次请求时，发往上游的请求 ≤ K，信封用完后剩余项记 `unavailable/budget`；⑤ 「不设金额上限」模式下 ①② 的请求不被拒绝，但每次仍有预留与结算记录；⑥ 新安装与恢复默认后是受限预算模式，每个付费科目都有非零的占位次数类上限、界面标「占位」，任何科目都不返回 `budget_cap_unset`；升级后用户改过的模式与上限不变 | US-07, US-19, US-30；M3、M6a |
