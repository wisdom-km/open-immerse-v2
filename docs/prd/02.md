## 2. 为谁

| 画像 | 场景 | 最在意 |
| --- | --- | --- |
| P1 研究生 / 博士生 | 每天读 arXiv 论文，公式密集（ML、物理、数学） | 公式与原文一致；左右对照；重开不重复花钱 |
| P2 科研人员 / 医生 | 读期刊 PDF，双栏或三栏、表格多（如 Lancet、NEJM） | 阅读顺序对；表格和图不丢；中文通顺 |
| P3 自带算力的进阶用户 | 有 GPU 服务器或付费 API，愿意自己部署解析服务 | 能接自己的服务与密钥；费用可控、可见 |

最低设备目标：Windows 10/11 64 位（2021 年后 i5 / Ryzen 5 级、8 GB 内存、核显）；macOS 13+、Apple M1、8 GB。8 GB 设备**不要求**在本地跑任何模型；重计算默认走托管 API（见下文「API 优先」）。

**API 优先**（Wisdom 2026-10-30 18:44，[ARCHITECTURE §7.0](./ARCHITECTURE.md#70-模型能力的默认来源api-优先wisdom-2026-10-30-1844)）：开发与最终用户一视同仁，凡是由模型提供的能力——Jev 质量评分、引擎 B（MiniCPM-OCR）、版面、多模态、OCR、翻译，以及文本问答与 TTS / ASR——有托管 API 时默认用 API，把对用户硬件的要求降到最低。本地模型部署是第二路线（Wisdom 2026-11-02 16:38，原文见 §9）：每个能力在设置里仍有「本地 / API」选择，两者走同一个接口，但本地只保留端口、契约和 stub，不在 M0/M1 实现，不下载模型，不设本地推理门禁，标为推迟，不删除。面壁 Jev 除外（同日 17:03，原文见 §9，AC-103）：契约里托管 API 与本地部署都是一等。最小托管 API 客户端在 M1，M6a 接入完整流程（§9 17:21）。`jev.route` 选 `local` 时可以不调用面壁 API。PP-DocLayout 与其余本机推理仍是第二路线。版面除外：它的「本地 / API」只在路线配置里，与引擎 A 的识别选择分开；托管版面 API 核实之前不发请求，默认也不再暂定本机（§3.5，D-D，Wisdom 2026-10-31；主次见 §9）。应用读取硬件画像，只用来给「本地」标可行性，以及在没有托管 API 或用户拒绝数据外发时决定推荐本地还是降级。没有 Key、拒绝外发或 API 不可用时，不静默改用别的付费服务、也不静默改成本地，按能力降级并提示。开发与测试用的 Key 只以环境变量提供（云端 Agent 经 Cursor Secrets 注入，开发者本机见 ARCHITECTURE §15.4），仓库不放、也不读 `.env`。

质量评估模型 Jev 的「API」由面壁开放平台托管（模型 `MiniCPM-OCR-Jev`，需要用户自己的面壁 API Key，价格**未核实**；Q9，Wisdom 2026-10-30 18:37）；「本地」保留，NVIDIA 机器首选 llama.cpp CUDA 构建。默认与推荐都是「API」；达到官方硬件要求（NVIDIA ≥ 8 GB 显存，或 Apple M 系列 ≥ 16 GB 统一内存）时给「本地」标「达到官方要求」，用户随时可改。两种选择对应用是同一个 worker `evaluate` 作业接口。配置键 `jev.route`（`'api' | 'local'`，默认 `'api'`）。选「本地」时对面壁 Jev API 的调用为 0，不偷偷回退（§9 17:03，AC-103）。自建远程 worker、自建 Jev Docker 服务放在「高级」里。开发机是 Windows + 32 GB 内存 + NVIDIA RTX 4070 12 GB 独显（Wisdom 2026-10-30 17:56 告知配置，18:44 告知系统）：开发走 API 路径；Jev 与 MiniCPM-OCR 的官方部署文档都没有覆盖 Windows，开发机上的本地部署标「不要求 / 未核实」，不作为任何里程碑的前提。依据见 [ARCHITECTURE §7.4](./ARCHITECTURE.md#74-质量评估的部署q9) 与[差异清单](./docs/v2-gap-and-changes.md) §2.3。
