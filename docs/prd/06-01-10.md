#### 6.1.10 架构评审其余项（AC-78–AC-83）

来自架构评审 P1-6、P1-7、P1-11、P2-1、P2-2、P2-4、P2-5、P2-6（ARCHITECTURE §4.3、§4.5.3、§5.3、§6、§10.5、§11、§13）。

| 编号 | 标准 | 对应 |
| --- | --- | --- |
| AC-78 | 借用多模态翻译只在装配期（CI + core 测试）：① 依赖矩阵中没有 `translation → repair`，加这条 import 的样例 PR 被 G5 拒绝；② 开关打开时，`translation` 经自己的 `TranslationProvider` 发出的请求用的是补救所用的同一服务商与模型，`translation` 源码中引用 `repair` 的次数为 0；③ 借用请求的预留 100% 记在多模态科目（AC-29）；④ 开关关闭且没有翻译服务时，借用请求为 0，按 ARCHITECTURE §7.0 降级 | US-22；M6c |
| AC-79 | Markdown 只有一条解析路径（CI + core 测试 + IPC 计数）：① renderer、各切片 `src/ui/` 与 `pure.ts` 传递上到达 `domain/parse/` 或解析库的路径为 0（G15），`pure.ts` 不导出 `renderMarkdown`；② 超过窗口预算的 `.md`（夹具含 1 MB 与 5 MB）经 `readFile` / `readBlocks` 取完全部块时，单条 IPC 消息都不超过预算，`ipc.oversize` 为 0；③ 同一 `revision` 下翻页取块不重新解析（解析次数为 1）；文件被外部修改后旧 `revision` 的 `readBlocks` 返回 `stale_revision` | US-24, US-27；M2 |
| AC-80 | 门禁与 PR 粒度（CI 样例 PR）：① 热点清单由脚本按 import 图算出：改 `contracts/src/ipc/<切片>.ts` 超过 30 行的样例 PR 不被 G11 拒绝，改 `ids.ts` 超过 30 行的被拒；② 契约 PR 非生成代码超过 200 行且描述里没有不拆理由时 G12 失败；③ 同一切片 UI 与 core 一起改的样例 PR 通过，UI 改动又改另一个切片 domain 的样例 PR 被 G18 拒绝；④ domain 纯函数超过 80 行不触发 G2，adapters 与 UI 中的函数超过 80 行触发；⑤ 必需检查是四条，依据是 2026-11-04 Anvil 查到的分支保护 API：`CI / node` 与 `CI / python-worker`（Linux，全部门禁）、`CI / worker-health-windows` 与 `CI / worker-health-macos`（不带模型的 worker 健康检查、`fixtures/protocol/` 与 `fixtures/parsing-rules/` 两侧） | US-14；M1 |
| AC-81 | 本机 worker 监管（core 测试 + e2e，Linux 与 Windows）：① `supervisor-state` 的每条转移都有用例，不在 ARCHITECTURE §10.5 图上的转移被拒；② 启动超时、握手失败进入 `crashed` 并按退避重启；协议主版本不符进入 `incompatible`，重启次数为 0；③ 重启次数用尽进入 `degraded`：依赖 worker 的能力记「不可用」，PDF 仍可按文字层基础档阅读（AC-11），用户「重新启动」后计数清零；④ 第二个应用实例拉起的 worker 数为 0；上次遗留的 worker 在新 worker 启动前被结束；应用退出后本机 worker 进程数为 0 | US-14, US-16；M3 |
| AC-82 | UI 事件登记（CI + 类型测试）：① `ui-events.ts` 中每个事件都登记发布方与订阅方切片；未登记的切片发布或订阅的样例 PR 被 G5 拒绝；② 载荷类型含函数、Promise 或类实例的样例编译失败；③ 新增事件的样例 PR 没有 ADR 编号时被拒 | US-09；M1 |
| AC-83 | 诊断保留量（core 测试 + 设置）：① 保留天数与体积上限可在设置中修改，修改后下一次滚动按新值执行；② 用一次完整解析（20 页）的合成用量事件夹具，默认上限下导出的诊断包保留全部用量事件与错误码（默认值 M2 实测后定标）；③ 超出上限时从最旧的记录开始删除；导出仍满足 AC-09、AC-10 | US-14；M2 |
