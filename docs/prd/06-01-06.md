#### 6.1.6 服务商适配层（AC-64）

来自 Wisdom 2026-10-30 19:45、19:46 的要求（§3.3「服务商」，ARCHITECTURE §7.9）。全部是契约测试、core 测试或门禁，用合成样例与本机假服务，不调用真实服务、不花钱。

| 编号 | 标准 | 对应 |
| --- | --- | --- |
| AC-64 | 服务商适配层（契约测试 + 门禁）：① 新增一家使用已有格式的服务商：样例 PR 只改 `packages/providers/src/registry/vendors/**` 与 `fixtures/providers/**`，`contracts`、切片、装配根、preload、设置页的改动行数为 0，全部门禁通过，设置页列出它；② 每个格式适配器（`openai-chat`、`anthropic-messages`、`gemini-generate-content`、`baidu-ocr`、`zhipu-layout-parsing`）都跑它支持的能力对应的共享套件，每条注册表记录至少跑 auth 与 errors 两套；③ 能力标记：`vision` 为否的模型收到带图请求时请求为 0、返回 `invalid_request`；`streaming` 为否时调用方仍收到 1 个块；补救只列出 `chat` 与 `vision` 都为是的模型，云 OCR 只列出 `ocr` 为是的模型；标记未知按否；标记超出格式能力的注册表记录在测试中失败；④ 每类 HTTP 错误样例映射到规定的 `ProviderFailure`（worker 侧格式由 TS 与 Python 两侧用同一批样例断言）；⑤ Key 只出现在请求头里，URL 中出现 0 次（百度 OCR 的 `access_token` 例外：它在日志与诊断包中被打码，换取 token 用的 API Key 与 Secret Key 只在 main）；Gemini 请求的 URL 不含 `key=`；⑥ 主机不在该服务商 `allowedHosts` 里时 main 拒绝授权，请求为 0；⑦ 每次发送都带预留（没有 `Reservation` 的调用无法通过类型检查），响应用量 100% 交给预算结算，服务商没报的用量记「未知」；⑧ 用户添加的自定义服务商只能选已有格式，同样经过外发同意与预算；⑨ 新安装时翻译、多模态补救、问答、云 OCR 的服务商选中数都为 0：设置列出该能力满足要求的全部注册表服务商，对任何服务商的请求为 0，能力按 ARCHITECTURE §7.0 降级；Gemini 注册表记录的默认端点格式是 `gemini-generate-content`，`openai-chat` 端点可以改选；百度 OCR 的注册表记录只有 access_token 一种鉴权方式 | US-06, US-07, US-32；M4、M5、M6c |
