### 6.2 质量与性能标准（待基准定标）

下表的「目标」一栏在基准集跑出基线前一律写「待基准定标」。定标时同时写明：测试设备、样本集版本、引擎与模型版本。

| 编号 | 指标 | 口径 | 目标 |
| --- | --- | --- | --- |
| QM-01 | 阅读顺序正确率 | 按页，块序列归一化编辑距离；分单栏 / 双栏 / 三栏及以上统计，并按顺序来源（`model` / `model_corrected` / `xy_cut`）与档位（文字层基础档、标准档、高质量档）分别报告；同时报告模型顺序被弃用的比例 | 待基准定标 |
| QM-02 | 正文字符错误率（CER） | 按每页的 `textLayer`（`trusted` / `untrusted` / `none`，AC-75）分开统计 | 文字层页：可信文字层原句改写数 = 0（确定性）；扫描页 CER 待基准定标 |
| QM-03 | 公式结构准确率 | 采用为「已核验 LaTeX」的公式中，与真值等价的比例；「源码核对」的公式与程序核对通过的「格式已核对」LaTeX 公式各自单独报告同一比例，不并入（AC-87、AC-89；后者度量「能渲染但错」这一已知代价） | 待基准定标 |
| QM-04 | 公式自动核验覆盖率 | 显示为已核验 LaTeX 的公式 / 全部公式；质量评分开、关分别报告；「源码核对」与「格式已核对」LaTeX 的公式各另列一行，不计入分子；评分关闭时另报告裁图与占位框的比例（AC-87、AC-89） | 待基准定标 |
| QM-05 | 质量评分阈值 | text / formula / table 分别定阈值 | 待基准定标（不得沿用上游默认值） |
| QM-06 | 首个可读页时间 | 打开到右栏出现第一页文字层通读 | 待基准定标（8 GB Windows 与 M1 分别测） |
| QM-07 | 整篇解析耗时 | 20 页论文，远程服务，按引擎分别统计 | 待基准定标 |
| QM-08 | 重开恢复时间 | 已翻译 15 页论文，重开到译文全部可见 | 待基准定标（v1 参考值：145 段约 1.3 秒，仅供对照） |
| QM-09 | 峰值内存 | 打开 50 页论文并滚动全篇，桌面进程合计 | 待基准定标 |
| QM-10 | 单篇费用 | 20 页论文，翻译 + 补救，按服务商记录 | 待基准定标；未知单价显示「未知」，不记为 0 |
| QM-11 | 安装包体积 | 不含模型权重 | 待基准定标 |
| QM-12 | arXiv 源码采用率 | 有源码的 arXiv 论文中，公式以「arXiv 源码」来源被采用的比例，按「已核验」与「源码核对」分开统计；与采用的公式真值等价率一并报告 | 待基准定标 |
| QM-13 | 高质量档「明显更好」判据 | PP-DocLayout_plus-L 相对 PP-DocLayoutV3 在 QM-01 与版面区域指标上的提升，及其耗时与内存代价 | 待基准定标（判据由用户拍板） |
| QM-14 | Jev 本机与远程评分一致性 | 同一校准集上本地与远程（面壁 API / Docker）评分的排序相关性；面壁 API 与 Docker 的分数是否一致也在此测（上游说一致，未实测）；各部署、面壁两个站点的阈值分别定标 | 待基准定标 |
| QM-15 | `.md` 外部修改到界面更新的时延 | 已打开的 `.md` 被外部编辑器保存（含「原子替换」式保存）到阅读器显示新内容；同时定文件事件去抖时长 | 待基准定标（Loom 建议 ≤ 1 秒、去抖 300 ms，均未实测） |
| QM-16 | 笔记库扫描时长 | 1 万个 `.md` 的文件夹，8 GB 基准机，从选定文件夹到文件树可用 | 待基准定标（Loom 方案未给值） |
| QM-17 | 单个 `.md` 的解析耗时 | 1 MB 与 5 MB 的 `.md`，8 GB 基准机，从打开到正文可见；结果用来定单文件大小上限与是否把解析移到 utility 进程（ARCHITECTURE §4.5.6） | 待基准定标（Loom 建议上限 5 MB，未实测） |
