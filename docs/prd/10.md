## 10. 术语

| 术语 | 含义 |
| --- | --- |
| 候选（Candidate） | 任一引擎 / 模型给出的未采用结果 |
| 采用版本（AcceptedPageRevision） | 某页当前生效的块、顺序、公式决策；译文区块记录按 `sourceBlockId` 挂在它的块上，见 ARCHITECTURE §8 |
| 译文区块记录（StoredTranslationBlock） | 一个原文段落级文本块的一个译文版本：正文是 Markdown（`oi-md/1`），另有模型、版本、校验结果、状态（成功 / 失败 / 重译中），见 ARCHITECTURE §8.1.1 |
| 公式决定摘要（formulaDigest） | 一个翻译块内全部受保护片段在当前采用版本下的写法与内容的哈希（写成 LaTeX 时是 LaTeX 的字节，显示裁图时是裁图的内容哈希，占位框时是页码；已核验、源码核对与程序核对通过同属 LaTeX 写法），是译文缓存键的一部分，见 ARCHITECTURE §8.1.1 |
| `MarkdownView` | 应用内唯一的 Markdown + 公式渲染组件，笔记、译文、问答回答与 `.md` 阅读器共用，见 ARCHITECTURE §4.5.4 |
| 笔记库（vault） | 用户用「打开文件夹」打开的一个 `.md` 文件夹；只读；链接解析与越界检查以它的根目录为界 |
| 文字层基础档 | 不依赖 Python 与模型，只用 PDF 文字层 + 几何规则 + 原页裁图的解析档位 |
| 补救（Repair） | 对有效低分的区域自动调用多模态模型重新识别或核验；v2 不以其他不确定证据触发（ARCHITECTURE §7.1）。评分关闭时多模态作为识别来源、用户手动「重新识别」都不是补救（§3.4） |
| 导入编排（ingest） | 无 UI 的切片，独占「解析 → 评分 → 采用 → 翻译」的跨切片顺序；下一步由已落库的事实重新推出，见 ARCHITECTURE §7.1 |
| 服务商适配层 | `packages/providers`：按 API 格式写的适配器，加按服务商写的注册表；新增服务商多数时候只加一条注册表记录，见 ARCHITECTURE §7.9 |
| 能力标记 | 每个（服务商, 模型）的 chat / vision / ocr / scoring / streaming 五个布尔值；只来自注册表或用户勾选，未知按否，见 ARCHITECTURE §7.9.3 |
| 外发检查（EgressCheck） | 每次连接前按（服务商, 能力, 目的主机）判断能否发送的端口；回环地址之外都算外发，见 ARCHITECTURE §7.0 第 6 条 |
| 外发同意事件 | `settings.onEgressConsentRequired`：core 通知 UI 弹出按服务商的确认。UI 不自行判断该不该问 |
| 撤回同意 | `settings.withdrawEgressConsent`：清掉某服务商的已同意记录，不改记为已拒绝。DESIGN 草案里的 `providerId` 即 `vendorId` |
| 预算预留（BudgetGate.reserve） | 每次外发付费调用之前向预算闸门申请额度，被拒则不发请求；单价未知时按请求数 / 页数 / token 上限计，见 ARCHITECTURE §7.8 |
| 核验（Verified） | 评分开关开着且路线含 Jev 时，候选程序核对通过且有效分数不低于阈值。来源一视同仁，含多模态。不是「模型说对」。路线不含 Jev 时程序核对通过不算已核验（§3.5）。与 arXiv 源码比对通过是否另算已核验仍待定 |
| 待评分 | 界面标记，不是评估状态：识别候选已采用用于阅读，但评估记录是 `error` / `unavailable`，或分数还不能用（阈值未定标、`fake/` 评估器）；不算已核验、不触发补救，评分恢复后自动补评 |
| 未评分 | 界面标记，不是评估状态：识别候选的评估记录是 `not-run`（原因码 `disabled`），用在正文、表格，以及没通过程序核对的公式上。程序核对通过的公式改标「格式已核对」，不再用这个徽标。不算已核验、不自动补救、不自动补评，用户可逐篇「为本文评分」，见 §3.4 |
| 源码核对 | 没有 Jev 分数时，通过整篇覆盖率与逐公式核对的 arXiv 源码公式的标记：显示 LaTeX、可进译文。当前不算已核验（是否改算已核验待 Wisdom 定，AC-87） |
| 程序核对 | 五项检查：可渲染、字符集、编号、位置、与文字层或邻近内容一致。Jev 开启且路线含 Jev 时，它和有效高分一起才标已核验。没有 Jev 分数时，通过则显示「格式已核对」的 LaTeX，不算已核验。挡不住「能渲染但错」的公式（AC-89） |
| 格式已核对 | 程序核对通过、又没有 Jev 有效高分时的公式显示决定 `format-checked-latex`。徽标暂定「格式已核对」，样式待 Loom。不算已核验。`checked-latex` 已并入这一条（AC-89，Wisdom 2026-10-31 01:14） |
| 占位框 | 裁图拿不到时显示的「图见原文第 N 页（点击查看）」，点击后左侧原文跳到该页（AC-89；样式待 Loom） |
| 重新识别 | 质量评分关闭时，用户对单个区域手动换一个来源再识别一次。公式通过程序核对时标「格式已核对」，不是补救（AC-90，待 Wisdom 确认） |
| 处理路线 | 四类积木（版面、识别来源、结果判定、兜底）的一份配置；换路线只改配置（§3.5，AC-91） |
| 预设路线 | 内置的四种组合：多模态+版面、仅多模态、OCR+版面、OCR+版面+Jev。过渡默认是多模态+版面（`multimodal-layout`）。正式全局默认待定，M0 实测后由 Wisdom 决定 |
| 公式来源（formula-source） | 从 arXiv 源码取得公式 LaTeX 并与版面区域对齐的模块，见 ARCHITECTURE §7.6 |
| 高质量档 | 引擎 A 使用 PP-DocLayout_plus-L 版面模型的档位；仅在基准证明明显更好后开放 |
| core / seam | 业务核心与其对外接口；UI 只经 seam 调用 core，见 ARCHITECTURE §2.1 |
