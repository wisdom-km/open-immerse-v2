### 3.2 范围外（v2 不做）

- v1 的一切浏览器能力：网页双语、悬浮 / 划词翻译、YouTube / X 字幕、content script、popup、MV3 manifest、右键菜单、`Alt+T`、站点规则。
- 学习中心（收藏词句复习）、非 PDF 文档翻译（TXT / MD / HTML）。`.md` 的**阅读**在范围内（S13），翻译不在。
- Markdown 阅读的延后项（Markdown 方案「推荐范围」的可延后档）：全文搜索、反向链接面板、块引用 `^id`、嵌入笔记 / 嵌入 PDF 页、Mermaid、front-matter 属性面板、标签、整篇「导出译文为 .md」、`.md` 的编辑与保存（接口已预留，ARCHITECTURE §4.5.7，实现另立项）、关系图谱、Obsidian 插件语法（callout 先按引用块显示）、`.md` 收进文献库。
- 手机 App、账号体系、跨设备同步、官方收费云、订阅、按账号计费、自有托管服务端。只保留接口设计余地：认证可以走账号 token（与 API Key 同一鉴权端口的另一种实现，ARCHITECTURE §7.9.5），`AccountSession` 在 v2 只注入空实现；不建订阅、不建计费、不建托管服务端，也不为此建目录（Wisdom 2026-10-30 22:44）。
- 写作辅助（带引用的大纲 / 段落草稿）：移出 v2 实现范围，作为后续阶段（Q5）。v2 只在架构中预留 `writing` 切片的位置、seam 草案、所依赖的数据模型与扩展点（ARCHITECTURE §4.4），并以 AC-27 验收这些保留接口。
- v1 数据迁移（Q8）：v2 从零开始，不做 v1 迁移器，不读取 v1 的 IndexedDB、导出包或旧本机服务目录。取舍：v1 数据存放在浏览器 IndexedDB，结构与 v2 的采用版本、锚点模型差别大，迁移器需要单独的格式解析、dry-run 报告、冲突处理和一整套测试，且只服务一次性迁移；不做它可以让 v2 的数据模型不受 v1 约束，并省掉原计划排在 M5 之后的整段迁移工作。代价：v1 用户的文献库、笔记、已存译文不会进入 v2，需要重新导入 PDF；v1 扩展不受影响，仍可打开查阅旧笔记。
- Unlimited-OCR（Q12）：不接入；上游支持坐标输出后再评估。
- 实时语音问答、完整富文本编辑器、TeX 编译、MathJax（公式只用 KaTeX，个别 KaTeX 不支持的宏显示原文加错误标记）。
- 整页多模态重建作为默认路径（v1 #189 的教训，见 v1 审查）。可选预设「仅多模态」不是全局默认，也不是过渡默认。过渡默认是「多模态+版面」（§3.5）。正式全局默认仍等 M0。
- 自动发版、自动签名公证（由人执行）。
