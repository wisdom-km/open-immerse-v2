### 8.1 Markdown 阅读的里程碑校正

Loom 方案「推荐范围」按 M2–M6（拆分前的编号）给了建议，下表对照本节的完整里程碑表做了校正。方案中的人日估算不进规格。

| 方案的建议 | 规格的安排 | 理由 |
| --- | --- | --- |
| `markdown` core（解析、KaTeX 安全参数、HTML 屏蔽）在 M2 | M2；切片骨架与 `latex-policy` 提前到 M1 | M1 要建全部空切片与契约包，G13–G16 从第一天约束新切片 |
| `MarkdownView` 接入笔记在 M2 | **改为 M5** | `notes` 切片在 M5 才交付，M2 没有笔记面板可接；M2 先用 `.md` 阅读器验证组件 |
| 接入译文在 M4 | M4，并与 D6 的译文区块记录同批 | 翻译切片在 M4，区块记录、缓存键与渲染一起改，避免先按旧模型存一遍 |
| 接入问答在「M5/M6，按 S8 所在里程碑」 | **定为 M5** | S8 问答在 M5 |
| 打开单个 `.md` 在 M2 | M2 | 只依赖文献库之外的文件读取与 `MarkdownView`，与 M2「阅读基础」同类 |
| 打开文件夹（笔记库）在 M3 | M3 | 大文件夹扫描要走可取消的任务，`jobs` 切片随 M3 的 worker 协议落地；库内 PDF 链接依赖 M2 的文献库 |
| 安全（越界、外链确认、大文件夹阈值、大文件截断）「随上面」 | 单文件相关（HTML、KaTeX、外链、图片、大文件）在 M2；笔记库相关（越界、符号链接、阈值）在 M3 | 跟着各自的入口交付 |
| D6 译文区块记录在 M4 | M4 | 同上 |
| D7 编辑预留在「M2–M3」 | **定为 M2** | 源码区间、往返测试、写入契约类型都随 `markdown` core 一起做，拆开会让 M2 的 core 形状在 M3 再变一次 |
