#### 6.1.7 架构评审 P1：外发检查、升级、Electron 加固（AC-65–AC-67）

来自架构评审 P1-2、P1-3、P1-9、P1-10（Wisdom 2026-10-30 19:57 批准；ARCHITECTURE §7.0 第 6 条、§8.4、§9、§10.1、§10.4）。

| 编号 | 标准 | 对应 |
| --- | --- | --- |
| AC-65 | 外发检查与远程 worker 的凭据（core 测试 + 契约测试）：① 目的主机分类：`127.0.0.1`、`::1` 与解析到回环地址的 `localhost` 不算外发；用户标为「本机可信」的主机不算外发（默认没有）；其余主机都算外发，包括标为「本地」但不在回环地址上的服务与远程 worker；② 服务商的主机不在登记的 `allowedHosts` 里时按新服务商处理；「外发前询问」开着时对话框出现 1 次，关着时按 AC-61 ⑦f 不弹、请求照常发送；③ `EgressCheck` 返回「询问」或「已拒绝」时连接数为 0，预留被释放；`ingest` 提交托管后端作业、服务商传输层、`worker-client` 连接远程 worker 三处都经检查，各有用例；④ `worker-client` 对远程 worker 附 `OI-Provider-Authorization` 的次数为 0，用例要求附带时返回 `credential_to_remote_refused`；`server` 模式的 worker 收到带该请求头的请求返回 400 `provider_credential_not_accepted`，创建的作业数为 0；⑤ 远程 worker 报出的托管后端（服务商与主机）出现在「数据去向」列表里，并按 AC-61 ⑦ 询问 | US-19, US-30；M3、M4 |
| AC-66 | 版本与升级（core 测试 + 协议测试）：① 存储：注入迁移失败后，原数据库文件逐字节不变，界面出现错误页并能导出诊断包；`app_schema` 高于应用支持版本的样例库以只读方式打开，写入次数为 0；JSON 文档的未知字段读入再写出后仍在，主版本更高的文档只读；② 协议：worker 主版本不在桌面支持范围内时，提交的作业数为 0，界面提示「worker 版本过旧」或「桌面版本过旧」，相关能力记「不可用（版本不兼容）」；次版本更高、带未知字段的响应照常解析；`426` 响应体可解析 | US-08, US-14；M2、M3 |
| AC-67 | Electron 加固（e2e + 单元测试）：① CSP 与导航（M1）：窗口实际生效的 CSP 与 `csp.ts` 常量逐字一致，不含 `unsafe-eval`；应用页面经 `oi-app://` 加载，`file://` 加载 0 次；`will-navigate`、`window.open`、`<webview>` 附加与权限请求的尝试 100% 被拒；② `oi-asset://`（M2）：符号链接越界、未登记的 `assetId`、`../` 与 `%2e%2e` 编码穿越、SVG、扩展名与内容不符的文件都返回 404；只接受 GET 与 HEAD；响应带 `nosniff`；③ Fuses（M8）：`npx @electron/fuses read --app` 读出的设置与 ARCHITECTURE §9 一致 | US-14；M1、M2、M8 |
