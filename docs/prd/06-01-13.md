#### 6.1.13 诊断日志（AC-101）

来自 Wisdom 2026-10-31 的批准，09:15 补充默认规则与 M0/M1 不做项。规格在 ARCHITECTURE §11。代码骨架在 M1；一键导出仍由 AC-09、AC-10、AC-83 在 M2 验收。

| 编号 | 标准 | 对应 |
| --- | --- | --- |
| AC-101 | 诊断日志骨架（core 测试，M1）：① 每次解析、每次 OCR、每次翻译有一条 `pipeline.run`，字段含 `run_id`（UUID，由 Node.js `crypto.randomUUID()` 生成，ARCHITECTURE §11）、`route`、`step`、`status`、`error_class`、`duration_ms`；论文正文、译文、提示词、密钥在日志中出现 0 次；② 调试模式默认关：从未开启时 `<应用数据目录>/debug/` 的文件数为 0。开启后调试日志写在该目录，早于 7 天的文件数为 0，目录总量不超过 50 MB，超出时按时间从旧到新删除（先到先清）；用户「清空」后该目录文件数为 0。关闭调试模式时先询问是否删除：用户确认删除则文件数为 0；用户不删除则已有文件留到触及 7 天或 50 MB。打开后的明细仍满足 ① 的禁止项；③ 用户没有主动选择导出或上传时，日志离开本机的次数为 0；④ 对 LangSmith 或其他云端追踪平台的依赖与调用为 0；把文档全文写入日志的次数为 0；⑤ 产品运行日志在 `<应用数据目录>/diagnostics/`，调试日志在 `<应用数据目录>/debug/`。这两处都是本机应用数据目录，不是 `packages/features/diagnostics/`。与 `docs/evidence/` 和 PR 描述里的 agent 工作记录分开 | US-14；M1 |
