### 3.1 范围内（v2）

| 编号 | 能力 | 说明 |
| --- | --- | --- |
| S1 | PDF 阅读 | 本地打开 PDF；PDF.js 原文浏览；右栏中文通读；点击互跳；字号、主题由 Loom 定（DESIGN.md D13、DS-26） |
| S2 | 解析 | 双引擎：A 模块化（版面 + 公式识别 + 阅读顺序 + 文字层优先 / OCR 兜底）为主力；B 为 MiniCPM-OCR 1.0 官方流水线（PP-DocLayoutV3 版面 → 裁剪 → 识别 → 组装）。是否调用由当前处理路线的识别列表决定（§3.5）：预设「OCR+版面」与「OCR+版面+Jev」把它用作对比，「多模态+版面」与「仅多模态」不调用，请求次数为 0（AC-92）；版面关掉时也不调用引擎 B，含自定义组合：它的 SDK 内部会跑 PP-DocLayoutV3，跑它等于悄悄把版面加回来，路线校验失败而不是静默跳过（D-E，2026-10-31 11:14）；按 API 优先，B 默认用面壁开放平台的 MiniCPM-OCR-1.0 文档解析 API（平台显示限时免费，长期价格**未核实**；只上传页面图，不上传 PDF；「外发前询问」开着时第一次使用前确认数据外发（§3.3）），「本地」选项是在 worker 里跑官方 SDK（§3.3）。A 的识别阶段（公式识别、OCR 兜底、表格）保留三条可选路径（Wisdom 2026-10-30 19:11；版面部署不在这三条里，与识别阶段分开，D-D，§3.5）：托管 API（候选是百度 AI Studio 的 PaddleOCR 托管 API，能否满足区域框、版本锁定与价格要求**未核实**，核实通过才出现在选项里）、本地部署、租用的 Linux 远程 worker；M3 开工前由 Wisdom 定最终选择；文字层对齐始终由我们自己的代码完成。阅读顺序（Wisdom 2026-10-30 21:12）：主顺序取 PP-DocLayout 版面模型给出的顺序，由我们的规则校验并兜底（页眉页脚、脚注与侧栏、图表与题注、跨栏跨页续接、XY-cut），规则集带版本；版面后端不给顺序时直接走兜底（ARCHITECTURE §7.10）。百度云通用 OCR 处理多栏页面不可靠，不作为阅读顺序或版面的主路线。A 的版面模型以 PP-DocLayoutV3 起步（此时对比须标注「版面同源」），基准另跑 PP-DocLayout_plus-L 对照，明显更好时作为「高质量档」供用户选择（Q10）。可选接入用户自带的云 OCR（百度、智谱）作为额外识别来源，只识别版面区域裁片里的文字；没有版面作业时不请求（D-E，AC-71）。无可用解析服务时降级为「文字层基础档」（Q2） |
| S3 | 翻译 | 只翻译自然语言；公式、引用编号、数字受程序校验保护；默认用户自带 Key 的翻译 API（BYOK，经服务商适配层接入；不预选，用户在设置里从全部服务商中选），「本地」选项是本机 OpenAI 兼容服务（§3.3）。未配置翻译服务时可借用已配置的多模态服务翻译：默认关，开启时提示会消耗多模态额度（Q11）。译文按原文段落分块存储（不是整篇 `.md`，也不是整页），每块每个版本一条记录，正文是 Markdown + LaTeX；翻译块是正文段落、标题、图表题注、脚注、列表项、引用块，表格和图显示原文裁图（只翻题注），独立公式走公式回退链、不翻译；先过公式校验再写，校验失败不存文本；可以单块重译，重译期间保留并显示上一版；整篇导出 `.md` 推迟到 v2 之后（Markdown 方案 D6，ARCHITECTURE §8.1.1） |
| S4 | 公式兜底链路 | 候选与采用分离；未核验公式显示原页裁图并保留 LaTeX 候选；有效低分的区域可调用多模态补救；仍不过继续显示原图。arXiv 论文可用作者源码校准公式（Q4）：识别编号与版本、下载并缓存源码、解析 TeX、与版面区域对齐，对齐通过的公式作为最高优先级候选，同样经过程序核对与质量评分；对齐失败回落到识别链路。用户关闭质量评分时（§3.4），通过整篇覆盖率与逐公式核对的源码公式显示 LaTeX、标「源码核对」（AC-87）；其他识别结果通过程序核对时显示 LaTeX、标「格式已核对」（`format-checked-latex`，AC-89），没通过的显示裁图，裁图拿不到时显示「图见原文第 N 页」占位框；「格式已核对」与「源码核对」都不算已核验。路线不含 Jev 时也一样，不论评分开关开或关（Wisdom 2026-10-31 01:14，修订 00:46）。徽标视觉待 Loom |
| S5 | 质量评估与补救 | 区域级质量评分（MiniCPM-OCR Jev，按 text / formula / table 分别评分；只有有效评分才算分，评分错误不算低分）。**所有识别结果**——引擎 A、引擎 B、云 OCR、arXiv 源码对齐、多模态（识别与补救、手动重新识别）——都必须有评估记录（Q1，Wisdom 2026-10-30 22:15 收窄，23:55 改口径）：Jev 开启时（评分开关为开，且路线的判定列表含 Jev）都经过评分，有效高分并且程序核对通过才算已核验；评分开关关闭时，正文与表格标「未评分」，公式由程序核对把关，通过标「格式已核对」，不算已核验。开关开着但路线不含 Jev 时不送评，公式程序核对通过同样标「格式已核对」，不算已核验（§3.5，RULES N-17，Wisdom 2026-10-31 01:14）。v2 的自动多模态补救**只**处理有效低分的区域（「明确不确定证据」入口还没有定义，定义之前不触发，ARCHITECTURE §7.1）；评分关闭时没有自动补救，多模态作为识别来源照常识别，用户可对单个区域手动「重新识别」（§3.4，Wisdom 2026-10-30 22:23）；用户开关 + 预算（受限 / 不设金额上限）。Jev 与多模态在设置中各有「本地 / API」选择，默认 API（Jev 的 API 是面壁开放平台；Q9，§3.3） |
| S6 | 文献库 | 按原 PDF SHA-256 识别；重复导入不重复解析；阅读进度；重开不重发翻译请求 |
| S7 | 笔记 | 选中原文或译文写笔记；锚点可重定位；重解析不删笔记；导出 Markdown；笔记正文按 Markdown + 公式渲染 |
| S8 | 文本问答 | 针对当前论文提问，回答带可点击的原文引用；回答按 Markdown + 公式渲染，流式输出时未写完的公式不闪烁。默认用户自带 Key 的对话 API，「本地」选项是本机 OpenAI 兼容服务（§3.3）；多模态模型与纯文本 LLM 都能用，走同一个服务商接口（Wisdom 2026-10-30 19:11）：多模态模型可以额外看到图、表、公式的区域裁图，纯文本模型只收文字与题注 |
| S9 | 基础语音 | 论文朗读 / 讲解音频（TTS）；语音转笔记（ASR）。默认用户自带 Key 的 API，「本地」选项走同一端口（服务商与本地模型 M7 选型，§3.3）。实时语音问答不在 v2 |
| S10 | 诊断 | 本机结构化日志（规格在 M0，代码骨架在 M1：每次解析 / OCR / 翻译记下路线、失败步骤、耗时；调试模式默认关；开启后调试日志最多 7 天且总量上限 50 MB，先到先清，可随时清空，关闭时询问是否删除；不记密钥与论文正文；只存本机）。一键导出脱敏诊断包仍在 M2。产品诊断日志的保留天数与体积仍等 M2 实测。不接云端追踪，不默认上传 |
| S11 | 远程 / 自建解析服务 | 同一个 Python worker 可本机运行，也可部署到用户自己的服务器；桌面端以同一协议（HTTP + SSE，Q7）调用（Q3） |
| S12 | UI 与业务核心解耦 | 改 UI 不改变核心行为、不让核心测试失败；核心测试只调用 seam、不渲染 UI（Q3，ARCHITECTURE §2.1、RULES §8）。这是每个功能的完成标准，验收见 AC-21 |
| S13 | Markdown 阅读 | 应用内一个统一的 `MarkdownView` 渲染笔记、译文、问答回答与 `.md` 文件，公式用 KaTeX，安全选项与公式模块同一份。可打开单个本地 `.md`（菜单、Ctrl/⌘+O、拖入、最近打开），也可打开整个文件夹作为笔记库：文件树、`[[wikilink]]`、`![[图片]]`、`[[笔记#标题]]`、失效链接标记、外部修改自动重载、后退 / 前进、大纲。`.md` 是独立入口，不进 PDF 文献库，只能链接到库内 PDF。v2 只读，编辑接口预留。设计见 [Loom 方案](./docs/design/md-reader.md)，架构见 ARCHITECTURE §4.5 |
