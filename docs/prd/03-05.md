### 3.5 处理路线（Wisdom 2026-10-30 22:41、22:44、22:45）

一条处理路线是四类积木的一份配置，不是写死的 A / B / C。换路线只改配置，不改代码。规则在 [ARCHITECTURE §7.12](./ARCHITECTURE.md#712-处理路线独立积木与声明式组合wisdom-2026-10-30-224122442245)，验收 AC-91–AC-100。界面只定行为，布局与文案待 Loom。

- **版面。** PP-DocLayout 先切出正文、行内公式、行间公式、图、表并排好阅读顺序，每个区块带坐标，再裁成小图交给识别和翻译。版面和引擎 A 的识别阶段是两个独立积木，各自一次作业（AC-96）。版面的「本地 / API」与引擎 A 识别阶段的「本地 / API」也是两个设置（D-D，Wisdom 2026-10-31）：版面只读路线里的版面部署，引擎 A 的设置只覆盖识别阶段。界面可以一键选预设，底下仍是这两个旋钮。可以关掉。关掉后整页只走多模态：坐标来自多模态返回的大致框，再用 PDF 文字层校正；对不上的只做页级显示，再按整页裁图、占位框依次降级（AC-95）。引擎 A 的识别（`parse`）、引擎 B、云 OCR 请求都为 0，不发整页（AC-71、AC-96，D-E，Wisdom 2026-10-31 11:14）。引擎 A 只消费版面裁片。引擎 B 的 SDK 内部会跑 PP-DocLayoutV3，跑它等于悄悄把版面加回来。识别列表含这三项之一且版面关着时，路线校验失败，原因码 `sources_require_layout`，不静默跳过。四个预设不改。已知代价：没有 OCR 兜底，只剩多模态，再按裁图、占位框降级。可以换成别的版面模型，换的是实现，core 不动。本地与远程的端口都保留。远程在有已核实的托管版面 API 之前只写自建远程 worker 的接口（与现有一样走 HTTP 加事件流），由用户在设置里选。版面选 API 在托管版面 API 核实之前不发请求。默认部署不再暂定本机（Wisdom 2026-11-02）：本机 PP-DocLayout 只留 `LayoutEngine` 端口与 stub，不实现、不下载模型，M0/M1 不测冷启动、单页耗时、峰值内存或是否 OOM。这些本地项标为推迟，不删除。标准档仍是 V3。plus-L 仍按 Q10、QM-13，不在本机 CPU 上作为 M0 测量。
- **识别来源。** 多模态、云 OCR、引擎 A、引擎 B、arXiv 源码。每个都能单独开关、单独选本地或远程。引擎 A 这一项的本地或远程只覆盖识别阶段，不改版面部署（D-D）。引擎 A 的识别、引擎 B、云 OCR 都要版面开着才请求。没有版面作业时这三项请求为 0，不发整页；路线里同时关掉版面又列入这三项，校验失败，不静默跳过（D-E，2026-10-31 11:14）。多模态在版面关掉时收整页。
- **结果判定。** Jev、程序核对、源码核对。评分开关优先：关闭时所有路线里的 Jev 判定都跳过，结果标「未评分」，路线配置不被改写（§3.4、AC-97）。Jev 开启时（开关开着且路线含 Jev），所有来源一视同仁：有效高分并且程序核对通过才标已核验。开关开着但路线不含 Jev 时不送评，新候选记 `not-run/disabled`；公式仍走程序核对（ARCHITECTURE §7.5 第 4、5 步），核对步骤不变。第 5 步通过标「格式已核对」，不算已核验（Wisdom 2026-10-31 01:14）。三个不含 Jev 的预设都是这条，开关关掉时标签相同。仅多模态做位置核对时，用经 PDF 文字层校正后的框（AC-95）代替版面公式区域。arXiv 在没有 Jev 分数时，通过核对的标「源码核对」；算不算已核验仍待定，当前不算。
- **兜底。** 识别不准或核对没过：先退到这个区块的裁图，再退到占位框「图见原文第 N 页（点击查看）」，点击跳到左侧原文。
- **预设**（Wisdom 2026-10-31，W-4）：正式全局默认等 M0 在同一批论文上对比四个预设的质量、面壁 API 单篇耗时、客户端内存（不含本地模型）之后，由 Wisdom 决定。在那之前，新安装与恢复默认的过渡预设是「多模态+版面」（id `multimodal-layout`），不是空，也不要求用户先选一条。来源优先级的默认顺序仍是现行提议，该项未决（AC-86、docs/backlog.md §8 W-4），这里不改顺序。

- **不含 Jev 的三个预设（Wisdom 2026-10-31 01:14，修订 00:46）。** 「多模态+版面」「仅多模态」「OCR+版面」的判定是程序核对，不含 Jev。不论评分开关开或关，它们都不提交 `evaluate`（开关开着时是因为判定列表不含 Jev），公式走第 4、5 步。第 5 步通过的显示决定是 `format-checked-latex`，徽标暂定「格式已核对」，样式待 Loom，不算已核验。第 4 步通过仍是「源码核对」，算不算已核验仍待定。能渲染但错的公式因此不再标已核验（docs/backlog.md §8 R-A，已通过改标签解决）。仅多模态没有编号字段时编号核对不过，仍是「M0 实测后决定」（同节 R-B）。手动「重新识别」在开关开着时仍不可用，三个预设也一样（AC-90；入口是否保留见 docs/backlog.md §8 W-1，开关开着进不进得去见同节 D-F）。
- **代价。** 按区块识别时一页可能要几次到十几次调用，每次都过预算闸门和外发同意。版面切错会连带后面出错，由阅读顺序规则校验和兜底（ARCHITECTURE §7.10）。
- **统一接口（22:44）。** 每种能力一个接口。本地 worker、第三方 API、以后我们自己托管的服务是不同实现。认证抽象成 API Key 或账号 token。订阅和计费不在 v2，只预留接口（§3.2）。
- **先按最保守的写、待确认：** 切换路线不改写已经处理过的文献；新解析的页和用户明确重跑的文献才用新路线。能否按篇切换，见 §9。
