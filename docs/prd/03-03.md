### 3.3 设置：模型能力的「本地 / API」与面壁开放平台（Q9，Wisdom 2026-10-30 18:37、18:44）

本节只定设置项与行为；页面布局、文案样式由 Loom 定（[DESIGN.md](../../DESIGN.md)）。原则见 [ARCHITECTURE §7.0](../../ARCHITECTURE.md#70-模型能力的默认来源api-优先wisdom-2026-10-30-1844)；Jev 的接口与错误映射见 [ARCHITECTURE §7.4「面壁 API」](../../ARCHITECTURE.md#74-质量评估的部署q9)，引擎 B 见 §7.1「引擎 B 的云端来源」。

每个模型能力一个「本地 / API」选择（API 优先；「本地」是第二路线，M0/M1 只留同一接口上的 stub，§9，2026-11-02）。Jev 的两条路线在契约里都是一等，键是 `jev.route`（`'api' | 'local'`），见下表与 AC-103。这个键不是 `ing_route`，也不是版面的 `RouteConfig.layout`：

| 能力 | 「API」（默认） | 「本地」（同一接口） | 行为 |
| --- | --- | --- | --- |
| 质量评估（Jev） | 面壁开放平台 `MiniCPM-OCR-Jev` | worker 内 llama.cpp CUDA 构建首选，Ollama 备选，macOS 走 Metal | 默认与推荐都是「API」；硬件画像只给「本地」标可行性（达到 / 不在官方要求内、官方文档是否覆盖该平台，ARCHITECTURE §7.4 推荐规则）。两者走同一个 worker `evaluate` 作业接口；切换只影响之后提交的评估；「本地」的 stub 或自检失败记 `unavailable`，不回退；「不启用」只表示本地结果不当作有效分数（AC-20、AC-103）。`jev.route` 默认 `'api'`，别的值拒绝、不改写成 `'api'`。选 `'local'` 时对面壁 Jev HTTP 的调用为 0，不因 stub 失败或缺少 Key 回退到 API（除非用户自己改回 `'api'`），不要求 `MODELBEST_API_KEY`；此时 Jev 不列入面壁的外发能力（引擎 B 若仍走面壁则照常询问）。本地实现现在是 stub，以后只替换 `quality/backends/local_engine`（AC-103） |
| 引擎 B（MiniCPM-OCR 1.0） | 面壁开放平台文档解析 `MiniCPM-OCR-1.0` | worker 内官方 SDK | 只上传页面图，不上传 PDF；平台显示限时免费，长期价格**未核实**；是否调用由处理路线决定（§3.5、AC-92）。「对比」只写在含引擎 B 的预设上 |
| 引擎 A 的识别阶段（公式识别、OCR 兜底、表格；不含版面部署） | 候选：百度 AI Studio PaddleOCR 托管 API，**未核实**，M3 开工前核实，核实通过才出现在选项里 | worker 内 PaddleOCR / PaddleX | 本行只覆盖识别阶段，不写版面部署（D-D，Wisdom 2026-10-31，§3.5）。三条路径都保留可选（Wisdom 2026-10-30 19:11）：托管 API（核实通过后）、「本地」、「高级」里的远程 worker（如租用的 Linux 服务器，跑同一份 worker）；默认值 M3 开工前由 Wisdom 定；没有可用解析服务时降级为文字层基础档（Q2）。版面的「本地 / API」只读路线里的版面配置；选 API 在托管版面 API 核实之前不发请求 |
| 多模态补救 | 用户自带 Key 的多模态服务（经服务商适配层；不预选，用户从全部服务商中选） | 本机 OpenAI 兼容服务 | 仍受补救开关与预算约束（AC-05、AC-06） |
| 翻译 | 用户自带 Key 的对话模型（经服务商适配层；不预选，用户从全部服务商中选） | 本机 OpenAI 兼容服务 | 未配置时可按 Q11 借用多模态（默认关） |
| 文本问答 | 用户自带 Key 的对话服务（经服务商适配层；不预选，用户从全部服务商中选） | 本机 OpenAI 兼容服务 | 多模态模型与纯文本 LLM 都可选，同一个服务商接口；模型是否接受图片取自它的「看图」能力标记（注册表预置或用户添加模型时勾选），不确定时按纯文本处理（AC-62） |
| TTS / ASR | 用户自带 Key 的服务（M7 选型） | 本机服务（M7 选型） | — |

云 OCR（百度、智谱）本身就是 API，仍是可选的额外识别来源，默认不启用（S2、AC-18）。没有版面作业时请求为 0，不发整页（AC-71，D-E）。

**服务商**（Wisdom 2026-10-30 19:45、19:46，ARCHITECTURE §7.9）：翻译、多模态、问答、云 OCR 的服务商都来自服务商适配层，支持 OpenAI 兼容、Anthropic Claude Messages、Google Gemini、百度（千帆 / 文心、百度 OCR、PaddleOCR）、智谱（GLM、GLM-OCR）、面壁（Jev、MiniCPM-OCR）等格式。设置里只列出满足该能力要求的模型（例如补救只列能看图的对话模型，云 OCR 只列 OCR 模型）；用户也可以选一种已支持的格式，填地址与模型名，添加自定义服务商，同样经过外发同意与预算。每个能力都列出全部服务商、不预选，由用户选；没选之前该能力按上表降级（Wisdom 2026-10-30 20:57；AC-64 ⑨）。Jev 与引擎 B 的 API 服务商仍是面壁开放平台。Gemini 默认用原生格式，OpenAI 兼容端点可以改选。

- **数据外发同意**（Wisdom 2026-10-30 19:11 批准；19:30 改为按服务商询问并加入开关；21:26 补充未作答与撤回，见 [DESIGN.md](../../DESIGN.md) DS-15、DS-16、DS-23、DS-24）：
  - **按服务商问一次，不是每一次请求都问。** 某个服务商第一次要收到数据前，弹一个对话框，列出当前选定把数据发给它的全部能力，每项写明会发什么（区域裁图与候选文本、整页图片、待翻译文本或问答上下文），并写明不上传原 PDF；用户同意后才发请求。例：面壁开放平台一个对话框，列出 Jev 评分与引擎 B 文档解析。
  - **新增能力要追加告知。** 已同意的服务商，之后又有能力要把数据发给它（例如用户把另一项能力改选到这家），该能力第一次请求前再弹一次，只列新增的能力。
  - **拒绝。** 只有点「不允许」才记为已拒绝。只影响这一个服务商、只影响对话框里列出的能力：这些能力对该服务商的请求为 0，也不改发给别的服务商，按本节「没有 Key、拒绝外发或 API 不可用」一条降级，并提示可改选「本地」；其他服务商上已同意的能力照常请求；追加告知被拒时，此前已同意的能力不受影响。开关保持开时，已拒绝的能力之后不再弹出，请求仍为 0。
  - **未作答。** Esc、关闭弹窗、退出应用都不记为已拒绝，也不记为已同意。这一次请求为 0，并按上一档降级。开关为开时，下次还要发送前再问（DESIGN DS-23）。未作答不写入「数据去向」。
  - **撤回同意。** 每个已同意的服务商都可以撤回（`settings.withdrawEgressConsent`）。撤回只去掉已同意，不改记为已拒绝。开关为开时，这些能力下次需要发送前再问，重新同意之前请求为 0。已经通过外发检查的在途请求不取消（DESIGN DS-24）。
  - **「外发前询问」开关。** 设置里有一个开关，默认开。只有用户在设置里亲自操作才会关闭，新安装、升级、恢复默认都不会关闭它。关闭后不再弹任何外发确认，请求照常发送（含此前已拒绝、尚未同意的能力）；这些项显示「询问已关闭」，底层的同意或拒绝记录保留。开关为开时，已同意显示「已同意」，已拒绝显示「已拒绝」。无论开关状态，设置里都显示「数据去向」列表：每个会收到数据的服务商、发给它的能力、每项的状态（已同意 / 询问已关闭 / 已拒绝）。重新打开开关后，没有在对话框里同意过的「服务商 + 能力」（含已拒绝与未作答），下次使用前照常询问；已经同意过的不再询问（按架构评审 P1-1，Wisdom 2026-10-30 20:57 确认保留）。从开改为关时，界面先确认一次，取消则保持开（DESIGN DS-15）；这次确认不是外发确认，core 不弹它，只在 UI 调用 `setEgressPromptEnabled` 之后才改变开关。从关改为开不确认。
  - **什么算外发。** 发往本机回环地址（`127.0.0.1`、`::1`）的请求不算外发；其余一律算，包括标为「本地」但不在本机的服务，以及用户的远程 worker。同一服务商换到不在登记范围内的主机时，开关为开则按新服务商再问一次，开关为关则不弹确认（ARCHITECTURE §7.0 第 6 条，AC-65）。
  - **谁来弹窗。** 只有 core 判定需要询问时，才发事件 `settings.onEgressConsentRequired`。UI 收到事件才弹出，不自己算该不该问（DESIGN DS-16）。允许与不允许调用 `answerEgressConsent`；未作答传 `granted: null`（进程退出、来不及调用时，core 同样视为未作答）。
  - 对话框的布局、文案样式与开关在设置里的位置由 Loom 定（[DESIGN.md](../../DESIGN.md) §4.2、§4.3）。规则见 ARCHITECTURE §7.0 第 6 条。
- **没有 Key、拒绝外发或 API 不可用**：不静默改用另一个付费服务，也不静默改成本地，按能力降级并提示去填 Key 或改选「本地」（ARCHITECTURE §7.0 表最后一列）。Jev 的情形：评分记为「待评分」，不算已核验、不算低分、不触发补救（AC-05、AC-18）；填好 Key 后自动补评。
- **Key 的保管**：最终用户的 Key 只存在本机安全存储。桌面里的服务商 Key 只发给对应服务商与本机 worker，不发给远程 worker（ARCHITECTURE §10.1）。开发与测试用的 Key（如 `MODELBEST_API_KEY`）只以环境变量提供：云端 Agent 经 Cursor Secrets 注入，开发者本机由开发者自己设为系统用户级或会话级环境变量；变量名登记在 ARCHITECTURE §15.4；仓库不放、也不读 `.env`；CI 不调用付费 API。Key 绝不进仓库、PR 描述、日志、测试快照与录制样例（RULES N-05、AC-09、AC-59）。
