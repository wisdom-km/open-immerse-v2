#### 6.1.15 Jev 的两条路线（AC-103）

来自 Wisdom 2026-11-02 17:03。只约束面壁 Jev。PP-DocLayout 与其余非 Jev 的本机推理仍是第二路线（§9 16:38）。`jev.route` 不是 `ing_route`，也不是版面的 `RouteConfig.layout`（D-D）。

| 编号 | 标准 | 对应 |
| --- | --- | --- |
| AC-103 | Jev 两条路线同一契约（①–④ 为 core 测试。最小托管 API 客户端在 M1，M6a 接入完整流程，§8）：① `settings/domain/backend-choice.ts` 的 Jev 键是 `jev.route`，取值只有 `'api'` 与 `'local'`，新安装默认 `'api'`；其他值校验失败，不改写成 `'api'`，不写入设置。② 两条路线实现同一个 `QualityEvaluatorBackend` 与同一个 `evaluate` 作业。`'local'` 现在是 `quality/backends/local_engine` 里的 stub，不下载模型，自己不去调面壁 API。③ `jev.route` 为 `'local'` 时，对 `api.modelbest.ai`、`api.modelbest.cn` 以及任何面壁 Jev HTTP 端点的调用为 0。不因 stub 失败、自检失败或缺少 `MODELBEST_API_KEY` 自动改回 `'api'`；只有用户把键改回 `'api'` 才走托管 API。`'local'` 不要求这把 Key。stub 失败记 `unavailable`，不记低分，不触发补救（AC-05）。④ `'local'` 时面壁的外发对话框与「数据去向」不列 Jev；引擎 B 仍走面壁 API 时只列引擎 B 并询问。`'api'` 时 Jev 仍按 AC-61 ⑦ 列入面壁。⑤ 切换 `jev.route`，以及以后用真实本机推理换掉 stub，不由单元测试验收。自建 Jev Docker 用 `jev.route='local'`，但走 `quality/backends/jev_http`（ARCHITECTURE §10.3），不走 `local_engine`。「改动只落在 `local_engine`」只约束 `local_engine` 路径：本机推理换掉 stub 的改动落在 `quality/backends/local_engine`。Docker 路径的同类约束：改动只落在 `jev_http` 的主机配置，该路径之外的代码改动为 0。验收仍是 CI 的 diff 路径检查，或 import-linter 契约（只有装配根按 `jev.route` 分支） | US-19；M1、M6a |
