# 验收结果

状态：现行

本目录收验收记录。测得的耗时、费用、内存、比例、阈值与请求次数不写进模板，也不在本说明里预填（RULES N-14）。

## 目录怎么组织

| 路径 | 作用 |
| --- | --- |
| `README.md` | 本说明 |
| `TEMPLATE.md` | 空模板。复制后再填。模板本身保持空白 |
| `<里程碑>/<编号>.md` | 一条标准的一份当前记录。有真实运行之后才新增 |

里程碑目录只用规格里已有的名字：`M0`、`M1`、`M2`、`M3`、`M4`、`M5`、`M6a`、`M6b`、`M6c`、`M6d`、`M7`、`M8`。

一条标准在一个里程碑里只留一份当前记录。再跑一次就改这一份；以前的正文留在 git 历史里。同一条标准可以按里程碑各有一份，目录名就是该份记录的里程碑（PRD §6、§8）。

[PRD §6](../../PRD.md#6-验收标准) 还要求：M1 之后把每条标准转写成这里的测试用例编号，测试名引用对应的 AC 编号。那是测试名映射，等测试真实存在再写。本说明不编测试名（RULES N-15）。

[ARCHITECTURE §3](../../ARCHITECTURE.md#3-目录结构) 把本目录写成 AC / QM 到测试用例的映射。映射与结果记录放在同一目录：映射等测试落地；结果记录用 [TEMPLATE.md](TEMPLATE.md)。本 PR 不改 ARCHITECTURE 正文。

现在没有填好的结果文件。Issue #43 所说「M0 第一份结果按此格式提交」，指以后那一次真实运行。

## 文件怎么命名

路径是 `docs/acceptance/<里程碑>/<编号>.md`。

编号使用 PRD 里已经写出的 AC 编号或 QM 编号，文件名与编号相同，扩展名 `.md`。保留编号里的连字符。文件名不加日期、SHA 或序号；日期和 SHA 写在正文里。

## 和 docs/evidence 的关系

`docs/evidence/<PR号>/` 放该 PR 的命令日志和截图（[RULES §4](../../RULES.md#4-测试运行纪律)，[ARCHITECTURE §11](../../ARCHITECTURE.md#11-可观测性)）。产品运行日志在本机应用数据目录。agent 工作记录在 PR 描述里。三处各写各的。

验收记录的「证据链接」指向 `docs/evidence/` 下的文件，或指向 CI artifact。日志正文留在证据目录，不抄进验收记录。大二进制不入库（RULES N-12）。真实 PDF 不入库。

证据按 PR 号分目录。验收记录按里程碑和编号分文件。两边用链接互指。

## 和差异清单 §7 的关系

[差异清单 §7](../v2-gap-and-changes.md#7-未核实的说法) 收录尚未核实的说法。上游说法和还没跑的测量记在那里。

[PRD §8](../../PRD.md#8-里程碑) 要求若干测量做完后，把结论写入差异清单 §7，包括面壁 API 参考样例、阅读顺序、四条路线对比，以及面壁 API 的单篇耗时、单篇费用、失败率与重试、客户端内存。那些结论引用本目录里对应记录的路径。

本目录不改写差异清单里的「未核实」，也不把测得的数字回填进 PRD 或 ARCHITECTURE。回填是以后的规格改动，且要等 Wisdom 拍板（N-14）。本 PR 不改差异清单正文。

## 和 QM 指标的关系

QM 指标在 [PRD §6.2](../../PRD.md#62-质量与性能标准待基准定标)。目标在基准跑出之前保持「待基准定标」。定标时同时写明测试设备、样本集版本、引擎与模型版本。这些数字不在模板里预填。

确定性标准必须满足，可以写成自动测试。QM 是质量或性能标准。基准脚本不作为 CI 门禁，结果写入本目录（[ARCHITECTURE §12](../../ARCHITECTURE.md#12-测试策略)）。

一条 QM 用同一份模板。编号栏写该 QM 的编号。基准还没跑、密钥不存在，或尚未由 Wisdom 拍板时，结果写「未核实」，不写测得的数字。

[ARCHITECTURE §12.1](../../ARCHITECTURE.md#121-评测记录) 的 `EvalRecord` 是路线对比的记录形状：文献 id、PDF sha256、路线 id、各来源请求数、评估状态计数、显示决定计数、失败原因码。形状留在规格里。本目录不另造带数字的样例，也不建 `fixtures/eval/`。合成样例仍按 §12.1，留到有真实夹具的改动。真实 PDF 不入库。

## 密钥

记录里不得出现密钥、令牌、证书、`.env` 内容、`Authorization` 头，或写在命令里的 Key。只记录密钥是否存在，用「存在」或「不存在」。可以写变量名，不写值（RULES N-05）。

## 状态行

本目录的 Markdown 在前四十行写状态行，供 `tools/check-docs` 识别。模板是 `状态：现行`。复制成结果记录后改为 `状态：报告`。

[docs/README.md](../README.md) 还没有同时含「路径」列和「状态」列的索引表。检查器因此保留一条既有的索引表缺失。不在那份索引里只加入本目录：表一旦出现，其余文档会被记成不在索引中；已有状态行又对不上检查器允许的四个词（现行、报告、历史草案、生成）时，还会被记成状态不一致。`docs/design-principles.md` 归 Loom，不能为了迁就这四个词去改它（N-10）。本 PR 只在 `docs/README.md` 加一句指针。
