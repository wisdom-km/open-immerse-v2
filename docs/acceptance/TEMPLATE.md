## 填写说明

- AC 编号：写 PRD 里的 AC 编号。QM 用同一格，写 QM 编号。
- 里程碑：与所在目录名一致。
- 构建或提交 SHA：这次运行所依据的构建或 git 提交。还没跑就留空。
- 系统、硬件、运行方式：这次的环境。硬件栏不预填容量、型号数量或耗时。运行方式写这次实际怎么跑。还没跑就留空。
- 结果：只能是 `PASS`、`FAIL`、`未核实` 三者之一。还没跑、密钥不存在，或尚未核实，写 `未核实`。没跑过的不写成 `PASS`（RULES N-15）。
- 证据链接：`docs/evidence/` 下文件的仓库相对路径，或 CI artifact 的 URL。没有就留空。不把日志正文贴进本文件。
- 执行人：这次实际执行的人或 bot。还没跑就留空。
- 日期：Asia/Shanghai 的日历日。还没跑就留空。
- 密钥是否存在：只能是 `存在` 或 `不存在`。不写值，不写请求头，不写 `.env` 内容。
- 不在本文件增加耗时、费用、内存、比例、阈值、请求次数或任何基准数字。这些等基准跑完并经 Wisdom 拍板后再回填规格。
