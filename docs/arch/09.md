## 9. IPC 协议（renderer ↔ main）

- 通道命名：`<feature>.<command>`（invoke，请求 / 响应）与 `<feature>.on<Event>`（事件订阅）。一个切片的通道全部定义在 `contracts/src/ipc/<feature>.ts`。
- 每个定义包含：请求 schema、响应 schema、错误码集合、是否幂等。preload 由这些定义**生成**，不手写。
- main 端 `ipc-router.ts` 统一做：校验发送方（只接受本应用窗口的 frame）、按 schema 校验载荷、调用切片的 `adapters/ipc-handlers.ts`、把异常映射为 `{code, message, retryable}`。
- 返回给 renderer 的数据不含密钥、不含绝对文件路径（用 `assetId` 换取受控的 `oi-asset://` 协议 URL）。
- 长任务一律返回 `jobId`，进度走事件，不在一个 invoke 里等待整篇完成。
- 文献库导入走 `library.import`（invoke）与 `library.importDropped`（dropped-file）（#166 决定，#168 契约 `packages/contracts/src/ipc/library.ts`）：只入库，不解析。`library.list`、`library.relocate` 同文件。各命令是否 `expose` 以该文件与 `packages/contracts/test/ipc-library.test.ts` 为准，不在这里写死。
- 解析与打开阅读仍走 `ingest.openDocument`（返回 `jobId`）。M2 ② 不接 ingest（#166 推后项）。
- `parsing.submitParse`、`quality.evaluateRegions` 仍是 `ingest` 调用的内部 seam，不注册为 IPC 命令。
- `oi-asset://` 服务下列资产：应用自有的内容寻址资产（`<userData>/assets/`），以及 `markdown` 切片登记的笔记库图片。处理器在 main（§1）；utility 启用后，资产登记表随 SQLite 在 utility，main 经 MessagePort 用 `assetId` 换取路径与允许的根目录后再做下列检查。renderer 中不出现 `file://`（AC-35）。处理规则（架构评审 P1-10，PRD AC-67 ②）：
  - 注册：`protocol.registerSchemesAsPrivileged` 只给 `standard: true`、`secure: true`（`standard` 是否必要待 M2 实测）；不给 `bypassCSP`、`supportFetchAPI`、`corsEnabled`、`allowServiceWorkers`、`stream`。M7 的 TTS 播放若需要 `stream`，经 ADR 再加。
  - 处理：用 `protocol.handle`；只接受 GET 与 HEAD；URL 形如 `oi-asset://asset/<assetId>`，只服务已登记的 `assetId`，其他一律 404；不重定向，不列目录。
  - 路径：每次读取都取文件与根目录的真实路径（`realpath`），文件必须仍在根目录内；符号链接指到根外即 404。
  - 类型：笔记库图片只放行 PNG、JPEG、GIF、WebP（不放行 SVG），扩展名与内容嗅探都要符合；响应带 `X-Content-Type-Options: nosniff`。
  - 测试：符号链接越界、未登记的 `assetId`、`../` 与 `%2e%2e` 编码穿越，都返回 404。
- 文献库 PDF 副本是第三类。它不并入 `<userData>/assets/`，也不并入笔记库图片。安全根是该条目的 `<dataRoot>/library/<libraryEntryId>/`。可读文件只有其中的 `source.pdf`，与 §8.2 的 `library/<sha256>/source.pdf` 是同一份副本。条目 id 就是该 SHA-256。本批发放、撤销与授权入口在 main。上面 utility 启用后资产登记表随 SQLite 迁移的通则不改，本句不另定进程或签名。renderer 只接收 `assetId`，不接收绝对路径，不接收整份 PDF 字节。
- 这一类只放行 `application/pdf`。内容须符合 PDF 头，并与文件名 `source.pdf` 一致。不符合、未登记、已撤销、副本不可读、符号链接出该条目目录、`../` 与 `%2e%2e`，都在协议层返回 HTTP 404。响应体为空，不含绝对路径，不含 IPC 错误码。响应带 `X-Content-Type-Options: nosniff`。不放行 SVG。上面的 PNG、JPEG、GIF、WebP 不扩大到 PDF。
- 向 renderer 发出 `assetId` 的 invoke 沿用本节已有的发送方规则，只接受本应用窗口里来源为 `oi-app:` 的主 frame。协议处理器不接受 renderer 提交的路径或字节。处理仍只接受 GET 与 HEAD。URL 仍是 `oi-asset://asset/<assetId>`。不重定向，不列目录。每次读取对文件和该条目目录做 `realpath`，文件必须仍在该条目目录内。
- 生命周期只定方向：`library.bindReadingAsset` 成功时给出 `assetId` 和 generation；`library.revokeReadingAsset` 按请求中的 `id` 与 generation 指向这一对。本批这两条以及两条页码命令的生产 IPC 已挂上，仍不等于重开已验收。重复登记是否沿用同一个 `assetId`、重载或崩溃后是否清表、以及先查表再查库，仍不在本节写成签名。不写 Range。
- `oi-asset://` 的响应只用 HTTP 状态。invoke 的结果才使用 `not_found`、`sender_rejected`，以及契约审定后的业务码。协议状态行不写这些码。
- 上面几条不授予 `bypassCSP`、`supportFetchAPI`、`wasm-unsafe-eval` 或 `blob:`。`connect-src` 按 ADR 0006 增加 `oi-asset:`（Wisdom 2026-11-10 10:50）。其余 CSP 指令不放宽。PDF.js 仍以 `isEvalSupported: false` 运行。不写 Range，不设置 `disableRange`。
- 外部链接：renderer 不导航、不 `window.open`；用户确认后调用 `markdown.openExternal`，main 只放行 `http` / `https` / `mailto` 并交给 `shell.openExternal`（§4.5.5）。
- Electron 安全基线（架构评审 P1-10，PRD AC-67）。以锁定版本的 [Electron 安全清单](https://www.electronjs.org/docs/latest/tutorial/security) 逐条验证：
  - 窗口：`contextIsolation: true`、`sandbox: true`、`nodeIntegration: false`，`webSecurity` 保持默认开启；不启用 `<webview>`。
  - 导航：`will-navigate` 一律阻止；`setWindowOpenHandler` 一律返回 `deny`（外部链接走 `markdown.openExternal`）；`will-attach-webview` 一律阻止。
  - 权限：`session.setPermissionRequestHandler` 与 `setPermissionCheckHandler` 一律拒绝；M7 的 ASR 若需要麦克风，经 ADR 只对它放行。
  - 页面来源：应用页面由自定义协议 `oi-app://` 提供（安全清单第 18 条），不用 `file://` 加载，因此下面的 `GrantFileProtocolExtraPrivileges` 可以关闭。
  - CSP：由 main 给 `oi-app://` 的响应加 `Content-Security-Policy` 头，常量在 `apps/desktop/src/main/security/csp.ts`。草案：`default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self' oi-asset:; font-src 'self'; connect-src 'self' oi-asset:; worker-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'`。不允许 `unsafe-eval`，PDF.js 以 `isEvalSupported: false` 运行。下列仍**待 M2 实测**：KaTeX 的行内样式是否需要 `style-src 'unsafe-inline'`；PDF.js 是否需要 `wasm-unsafe-eval` 与 `blob:` 的 worker；PDF 数据经 `oi-asset://` 加载是否需要 `supportFetchAPI`。`connect-src oi-asset:` 已按 ADR 0006 采纳。任何进一步放宽都要 ADR，并写到期里程碑。PRD AC-67 ① 在 M1 用 e2e 读出窗口实际生效的 CSP，与常量逐字一致。
  - Fuses：打包时用 `@electron/fuses` 设置——`RunAsNode` 关、`EnableNodeOptionsEnvironmentVariable` 关、`EnableNodeCliInspectArguments` 关、`EnableCookieEncryption` 开、`OnlyLoadAppFromAsar` 开、`EnableEmbeddedAsarIntegrityValidation` 开（各平台是否支持**未核实**）、`GrantFileProtocolExtraPrivileges` 关。依据 Electron `docs/tutorial/fuses.md`（2026-10-30 查阅 main 分支），M1 按锁定版本复核；M8 打包后用 `npx @electron/fuses read --app <应用路径>` 核对（PRD AC-67 ③）。
