## 6. 文件与函数大小

统计口径：物理行数（含空行与注释）。生成文件、协议样例、迁移 SQL、锁文件不计，但必须在 `tools/check-file-size/allowlist.json` 里登记路径模式与理由。

| 对象 | 建议上限 | 提示数（不因此失败） |
| --- | --- | --- |
| 普通源文件（`.ts` / `.tsx` / `.py`） | 400 行 | **600 行** |
| 入口与装配文件（`main/index.ts`、`composition-root.ts`、`preload/index.ts`、`renderer/main.tsx`、`oi_worker/__main__.py`） | 100 行 | **150 行** |
| React 组件文件 | 250 行 | 400 行 |
| 测试文件 | 600 行 | 800 行 |
| 函数 / 方法 | 50 行 | 物理行数不再单独失败。ESLint `max-lines-per-function` 为 off。ruff PLR0915 是语句数 80，不是行数，仍失败 |
| 圈复杂度 | 10 | **15** |
| 函数参数 | 3 个 | 4 个（评审口径。eslint 没有 `max-params`，本轮不新增自动检查） |

- **domain 纯函数的例外**（架构评审 P2-1）：`features/*/src/domain/**` 与 Python core（§2.3）里的纯函数不受函数物理行数限制，仍受圈复杂度约束。文件行数只作提示；按「一个不变量一个文件」拆分（例如 `integrity-check` 的每条检查一个文件），评审看一个文件承接几个不变量（RULES §5 第 2 条）。函数物理行数的 ESLint 规则现为 off，不是 warn，因为 lint 使用 `--max-warnings 0`。domain 路径上的 off 仍然留着。ruff PLR0915 计语句数量，`max-statements` 为 80，不是物理行数。`workers/parser/pyproject.toml` 本轮不改，已有的 per-file-ignores 不扩大也不删除。圈复杂度仍约束这些函数。adapters、application、UI 与入口不再因函数物理行数失败，仍受圈复杂度和职责审查约束。
- 上表的数是提示，不是单独否决的条件。`check-file-size` 打印普通源文件 600、入口 150、组件 400、测试 800 的超过项，不因此失败。`check-pr-size` 打印非生成增删合计，超过 600 或只改 contracts 时超过 200 都不因此失败，也不再读取理由字符串。git 失败仍然非 0。分支保护不改。改这些脚本之前的 CI 失败不能记成通过。
- 功能归到对应的模块和文件。一个文件只承接一种职责。不同功能不堆进同一个文件。依赖只沿 §5，界面只经 seam 调用 core。
- 总 diff、单文件行数、职责是否耦合，分开审查。合理规模和为什么这样分，写在 PR 里。用户举过的几千行或一万行只是例子，不是额度。不为每个小函数单独建文件。拆开后仍共享一大块可变状态，不算解耦。不压缩格式，不删测试，不用没有语义的拆分去迎合行数。
- 超过建议上限时，PR 描述写明为什么这样分。豁免进 allowlist 仍只能经过 ADR，并写**到期里程碑**。名单不再当作行数放行开关。生成文件的 ignore 仍然跳过。坏的名单仍然失败。
- 行数落在阈值里不等于职责单一。评审仍按 RULES.md 检查职责数量与依赖扇出。
- 行数继续统计，用来看规模和审查注意力，不单独否决。同一功能可以按领域、编排、适配、界面和测试分成多个文件。不把整项功能塞进一个文件，也不为每个小函数建文件。可分开交付的功能可以分 PR。不为了行数拆成不能独立工作的碎片。
- 公开参考是 Google Engineering Practices 的 Small CLs（https://google.github.io/eng-practices/review/developer/small-cls.html）与 What to look for in a code review（https://google.github.io/eng-practices/review/reviewer/looking-for.html）。原文鼓励小而完整的变更，写明没有统一的太大门槛，审查者仍可以因为变更太大要求拆分。那两页的行数例子不是本项目门槛。取消 600 的硬阻断是本项目的决定，不是所有大公司的惯例。Wisdom 2026-11-22 15:02、15:03。
- `check-hotspots` 只打印 `composition-root.ts` 与 `slots.ts` 的 diff 行数。超过 30 不失败，也不检查职责或依赖。热点改动的风险仍要在 PR 里说明。依赖方向仍由 G13 与 G15 拦。
