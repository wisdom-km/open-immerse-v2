### 7.13 评分、路线、外发与预算的汇合（Wisdom 2026-10-31 13:14）

M3 交付这一张表，验收是 PRD AC-102。它把已经写在 PRD AC-85、AC-89、AC-97 里的规则收成一处，并标出它们接到外发同意（§7.0 第 6 条、§7.4「与外发同意的配合」、PRD AC-61 ⑦）和预算（§7.8、PRD AC-06、AC-63、AC-98）时的结果。不新增行为，不新造原因码，不改那三条的含义。与 AC-85、AC-89、AC-97 的字面冲突时，以那三条为准，并先改这张表。

显示决定仍只有 §7.5 的五种。不增加矢量重绘。降级链仍是 LaTeX → 原页裁图（`source-crop`）→ 占位框（`page-placeholder`）。v1 审查与 README 已经写明矢量重绘不进 v2；本节只把这条和汇合表放在一起，避免读表的人另造一种显示。

读表：

- 「路线含 Jev」只指判定列表含 `jev`。四个预设里只有 `ocr-layout-jev` 含 Jev。`multimodal-layout`、`multimodal-only`、`ocr-layout` 不含 Jev，在本表的评分列行为相同；它们在版面与识别上的差别仍按 §7.12、D-E，不在本表改。自定义组合按判定列表是否含 `jev` 归入这两类。
- 写「任意」的外发列，四种都算进这一行：已同意、已拒绝且询问开、未作答且询问开、询问关。写「任意」的预算列，也四种都算：受限且未到顶、受限且已到顶、受限且单价未知又没有次数类上限、不设金额上限。AC-102 要求这些组合都跑到，断言与该行相同。
- 外发列与预算列只约束会出网的 Jev。目的主机是回环地址的「本地」Jev 不算外发、不记金额（§7.0 第 6 条、§7.8 第 1 条）。开关关着，或开关开着但路线不含 Jev 时，本地 `evaluate` 同样是 0 次。
- 两道闸门同时拒绝时，不新造合并原因码，也不规定先返回哪一个。AC-102 把外发拒绝和预算拒绝分开断言。单独拒绝时的原因码只使用 AC-61 ⑦、AC-06、AC-63 与 §7.8 已经写明的那些。
- 假评估器（M3）对真实 Jev 的请求为 0。`fake/` 的 `scored` 永远不使候选成为已核验（AC-84）。
